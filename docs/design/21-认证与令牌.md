# 21 认证与令牌

> **本文回答**：如何证明身份，凭据如何签发、轮换、撤销与存放。
>
> 初稿：2026-10-22 · 最近更新：2026-10-22

## 一、登录方式

四种方式最终收敛到同一身份主体与同一套令牌：

| 方式 | 凭据 | 说明 |
|---|---|---|
| 密码 | 账号 / 邮箱 / 手机号 + 密码 | 密码以 bcrypt 存储 |
| 邮箱验证码 | 邮箱 + 一次性验证码 | 免密登录、注册 |
| 手机验证码 | 手机号 + 一次性验证码 | 免密登录、注册 |
| 第三方授权 | OAuth2 授权码 | 首次授权创建本地用户与绑定 |

**注册**走邮箱或手机验证码；注册成功即签发令牌，不要求二次登录。密码登录要求账号已存在，不承载注册。

**登录失败的表达**：

- 账号不存在与密码错误合并为 `CREDENTIALS_INVALID` —— 分开返回会让攻击者枚举账号。
- 账号停用、注销、删除分别返回对应标识；三者都不得签发令牌。
- 登录端点受频率限制；失败次数与来源 IP 都计入。

### 1.1 账号生命周期

| 动作 | 前置条件 | 副作用 |
|---|---|---|
| 注册 | 邮箱 / 手机验证码 | 创建用户；签发令牌 |
| 密码重置 | 邮箱 / 手机验证码（重置密码场景） | 更新密码；**撤销全部会话** |
| 修改密码 | 已登录 + 旧密码 | 更新密码；**撤销其他会话** |
| 绑定邮箱 / 手机 | 已登录 + 对应验证码 | 更新绑定；不隐式合并账号 |
| 绑定 / 解绑第三方 | 已登录 | 建立或解除绑定；**不得解除最后一个登录方式** |
| 注销 | 已登录 + 密码 + 原因 | 状态转注销；30 天冷静期；**撤销全部会话**；数据保留 |
| 恢复 | 冷静期内 + 邮箱 / 手机验证 | 状态恢复正常 |
| 删除 | 冷静期后或管理端操作 | 软删除；按保留策略处理 |

**改密与注销必须撤销会话**：身份状态已经变化，不能等令牌自然过期。撤销是状态迁移的一部分，不是可选的清理动作。

**绑定与解绑是显式动作**：邮箱或手机重合不自动合并账号；解绑最后一个登录方式会让用户永久失去入口，必须在服务端拒绝。

## 二、第三方授权

```
浏览器 ──▶ 授权页（带 platform）──▶ 第三方
                                   │ 回调
                                   ▼
后端 ──▶ 校验 state ──▶ 换取第三方身份 ──▶ 关联或创建本地用户 ──▶ 签发令牌
```

| 约定 | 内容 |
|---|---|
| **state** | 服务端生成一次性随机串，写入 Redis，TTL 10 分钟；回调时读取并删除，重复使用即拒绝 |
| **state 内容** | 平台标识与意图（登录 / 绑定），不携带用户身份 |
| **平台白名单** | `platform` 必须命中已配置的平台；回调地址由服务端按平台决定，不接受请求方传入 |
| **绑定** | 同一用户可绑定多个第三方账号；绑定与解绑是显式动作 |
| **不隐式合并** | 第三方身份只用于识别；邮箱相同不自动合并账号 |
| **失败** | 第三方不可用时该登录方式不可用，其他方式不受影响 |

**state 是防 CSRF 的核心**：缺失、过期或不匹配即拒绝；state 必须一次性消费，否则重放可完成一次未经用户发起的授权。

## 三、令牌形态

采用双令牌：access 用于接口调用，refresh 仅用于换取新令牌。

| 客户端 | access | refresh |
|---|---|---|
| 读者端（SPA 直连） | 不透明引用令牌，`at_` 前缀 | 不透明引用令牌，`rt_` 前缀 |
| 管理端（BFF） | JWT HS256 | 不透明引用令牌，`rt_` 前缀 |

**为什么两端不同**：

- 读者端需要「签发即能撤销」。不透明令牌每次校验回源，撤销立即生效；长度固定、无 JSON 解析开销。
- 管理端经 BFF，网关需要在不回源的情况下做粗粒度识别；JWT 的 canonical 校验足够，细粒度权限仍由服务端判定。
- **两端都不把权限写进令牌** —— 令牌只回答「是谁」，权限每次由服务端判定。

**令牌携带的最小声明**：用户标识、设备标识、会话标识、签发者、令牌类型、签发与过期时间。不携带角色、菜单、接口权限。

**生命周期**：

| 项 | 默认值 | 含义 |
|---|---|---|
| access TTL | 120 分钟 | 过期后必须刷新 |
| refresh 空闲 TTL | 7 天 | 连续未使用即失效 |
| refresh 绝对 TTL | 30 天 | 无论是否活跃，到期即失效 |
| grace 窗口 | 30 秒 | 并发刷新的宽限 |
| 时钟偏差容忍 | 30 秒 | 过期判断的余量 |

**120 分钟不是安全窗口**：access 每次校验都回源会话，撤销立即生效；TTL 只决定用户无操作后是否需要重新登录，不影响吊销。

## 四、会话模型

每次登录创建一个会话，令牌绑定到会话：

| 字段 | 用途 |
|---|---|
| 会话 ID | 撤销与审计的最小单位 |
| 用户 / 设备 | 身份绑定；设备不符即拒绝 |
| family | refresh 轮换链的标识；重放时整族撤销 |
| 创建 / 最近使用 / 过期时间 | 空闲与绝对过期判定 |

**轮换与重放**：

```
refresh A ──▶ 签发 refresh B，A 标记已用
                  │
并发/重试再次使用 A ──▶ grace 窗口内：返回同一对 B
                      └─ 超出窗口：判定重放，撤销整个 family
```

- refresh **一次性使用**；每次刷新都轮换。
- **重放检测以 family 为单位**：单个 refresh 被重复使用，说明它可能已泄漏；撤销整族，而不是只撤销这一个。
- **grace 窗口吸收并发刷新与网络重试**：同一旧 refresh 在 30 秒内再次使用，返回同一对结果，不视为攻击。
- 轮换结果加密存储，密钥由旧 refresh 派生；不把新令牌明文写入日志。

**登录模式**：

| 客户端 | 模式 | 效果 |
|---|---|---|
| 读者端 | 多点 | 同一用户 + 同一设备只保留最新会话；其他设备不受影响 |
| 管理端 | 单点 | 新登录撤销该用户全部旧会话 |

**撤销**：

| 动作 | 范围 |
|---|---|
| 登出 | 当前会话 |
| 强制下线某设备 | 该用户在该设备的全部会话 |
| 停用 / 注销 / 改密 | 该用户全部会话 |
| refresh 重放 | 整个 family |

**会话存储是权威**：令牌校验必须回源会话存储；存储不可用时**拒绝请求**（fail-closed）。查不到会话不等于有效，不能因为存储故障放行。

## 五、客户端形态与传输

| 客户端 | access 存放 | refresh 存放 | 传输 |
|---|---|---|---|
| 读者端 SPA | **内存**，页面刷新后重新获取 | **HttpOnly + Secure + SameSite Cookie** | `Authorization: Bearer`；刷新走同源 Cookie |
| 管理端 BFF | BFF 内存 / 服务端会话 | HttpOnly Cookie | 浏览器只与 BFF 交互；BFF 携带令牌访问后端 |
| 原生 App（未来） | 系统安全存储 | 系统安全存储 | 同读者端 |

**不得把令牌放进 `localStorage` 或 `sessionStorage`。** 任何 XSS 都能读取并外传；HttpOnly Cookie 至少让脚本读不到 refresh。access 放内存的代价是页面刷新后多一次刷新请求，这个代价远小于令牌被脚本窃取。

**设备绑定**：令牌签发时写入设备标识；校验时要求请求携带的设备标识与令牌一致，不一致返回 `UNAUTHENTICATED`。空设备标识归一化为 `default`，但仍需一致。

**传输约定**：

- 只经 HTTPS；Cookie 必须 `Secure`。
- 刷新端点使用同源 Cookie 与 CSRF 防护；不把 refresh 放在 URL 或查询参数。
- 登出同时清除服务端会话与客户端 Cookie。

## 六、关键决策

### D1 双令牌，access 与 refresh 职责分离

- **约束**：access 需要短寿命、低延迟；refresh 需要长寿命、可撤销。
- **备选**：单令牌；或每次请求都刷新。
- **选择**：access 短寿命；refresh 只用于换新，且一次性轮换。
- **代价**：客户端需要处理刷新与并发。
- **重审触发**：access 校验的延迟成为瓶颈。

### D2 读者端用不透明令牌，管理端用 JWT

- **约束**：读者端要求即时撤销；管理端经 BFF，需要快速识别。
- **备选**：两端统一 JWT；或两端统一不透明。
- **选择**：读者端不透明，管理端 JWT + 不透明 refresh。
- **代价**：两套 codec 与测试矩阵。
- **重审触发**：管理端也需要即时撤销且能接受回源开销。

### D3 令牌不承载权限

- **约束**：权限变更必须及时生效；令牌是自包含快照，签发即定。
- **备选**：把角色写进令牌；或令牌 + 版本号。
- **选择**：令牌只带身份；权限每次由服务端判定。
- **代价**：每次鉴权多一次权限查询（由缓存缓解）。
- **重审触发**：权限判定成为请求链路的瓶颈，且能接受有界陈旧。

### D4 refresh 一次性轮换，family 级撤销

- **约束**：refresh 泄漏后必须能止损；并发刷新不能误伤。
- **备选**：refresh 永久有效；或每次刷新不轮换。
- **选择**：一次性轮换；重放撤销整族；30 秒 grace 吸收并发。
- **代价**：需要存储轮换历史与 family。
- **重审触发**：出现无法用 grace 吸收的合法并发模式。

### D5 会话存储权威，fail-closed

- **约束**：放行等于吊销机制失效。
- **备选**：存储不可用时放行；或只对敏感接口拒绝。
- **选择**：拒绝。
- **代价**：Redis 故障时登录态请求全部失败。
- **重审触发**：出现比拒绝更安全的降级路径。

### D6 令牌绑定设备

- **约束**：令牌被复制到另一设备后应失效。
- **备选**：只绑定用户；或额外绑定 IP / UA。
- **选择**：绑定设备标识；不绑定 IP（移动网络会变）。
- **代价**：换设备需要重新登录。
- **重审触发**：出现合法的多设备共享场景。

### D7 OAuth state 一次性、平台白名单

- **约束**：回调可能被 CSRF 与开放重定向利用。
- **备选**：无 state；或把回调地址交给客户端。
- **选择**：服务端生成一次性 state；平台与回调地址由服务端决定。
- **代价**：需要 Redis 存储短期状态。
- **重审触发**：出现无法使用 state 的第三方流程。

### D8 登录失败合并凭据错误

- **约束**：分开返回会泄漏账号是否存在。
- **备选**：分别返回「账号不存在」与「密码错误」。
- **选择**：统一 `CREDENTIALS_INVALID`。
- **代价**：用户无法从错误中判断是账号还是密码问题。
- **重审触发**：产品要求更细的引导，且能接受枚举风险。

## 七、不变量

- [ ] 令牌只携带身份，不携带权限。
- [ ] access 过期必须刷新；refresh 一次性轮换。
- [ ] refresh 重放撤销整个 family。
- [ ] 会话存储不可用时拒绝请求，不把「查不到」视为有效。
- [ ] 令牌校验要求设备标识与签发时一致。
- [ ] 令牌不出现在 URL、查询参数与日志中。
- [ ] SPA 不把令牌放进 Web Storage。
- [ ] OAuth state 一次性消费；平台与回调地址由服务端决定。
- [ ] 账号状态变化撤销全部会话。

## 八、失败与降级

| 情形 | 行为 | 用户可见后果 |
|---|---|---|
| 令牌缺失 / 格式错误 | `UNAUTHENTICATED` | 需登录 |
| 令牌过期 | `LOGIN_EXPIRED`；客户端尝试刷新 | 无感或需重新登录 |
| 会话不存在 | `UNAUTHENTICATED` | 需重新登录 |
| refresh 重放 | 撤销 family，返回未认证 | 全部相关设备下线 |
| 会话存储不可用 | 拒绝 | 登录态请求失败 |
| OAuth state 无效 | 拒绝回调 | 重新发起授权 |
| 第三方平台不可用 | 该方式不可用 | 使用其他登录方式 |
| 账号停用 / 注销 | 拒绝签发与校验 | 无法登录 |

## 九、边界与重新审视

- **不做**：社交登录之外的联合身份、跨站点 SSO、令牌内嵌权限。
- **重新审视**：原生 App 需要系统安全存储；管理端需要即时撤销；refresh 的并发模式超出 grace 窗口。
