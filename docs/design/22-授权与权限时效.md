# 22 授权与权限时效

> **本文回答**：注册用户能做什么，权限变更后多久生效，缓存如何保证不越权。
>
> 初稿：2026-10-22 · 最近更新：2026-10-22

## 一、模型

采用 **RBAC**：用户 → 角色 → 资源授权。

授权对象有两类，独立存储、同属一个角色：

| 对象 | 回答 | 使用方 |
|---|---|---|
| **接口资源** | 能否调用某个服务端操作 | 授权中间件，服务端唯一裁决 |
| **菜单资源** | 界面是否可见、导航如何渲染 | 前端渲染 |

**菜单资源不参与服务端判定。** 前端隐藏按钮只是体验优化，任何接口调用都在服务端重新判定。把菜单当权限用，等于让前端成为裁决者。

**管理员是「用户 + 角色」，不是独立主体。** 角色带状态；默认角色用于新用户初始化。`root` 是明确的超级管理员角色，绕过权限匹配，其成员变更属于高风险操作，必须审计。

## 二、判定链

```
请求 ──▶ 认证中间件：确认身份
          └─▶ 授权中间件：uid + 方法 + 路径
                    ├─ 路径未登记 ──▶ 拒绝
                    ├─ 命中 root ──▶ 放行
                    └─ 角色 → 接口资源 ──▶ 放行 / 拒绝
```

| 环节 | 规则 |
|---|---|
| 取身份 | 从认证中间件写入的上下文取用户标识；取不到即拒绝 |
| 路径匹配 | 方法 + 路径；支持路径参数与通配符；路径先规范化 |
| 未登记路径 | **拒绝** —— 服务端不能对「没登记过的接口」给出放行默认值 |
| root | 绕过资源匹配，直接放行 |
| 角色授权 | 用户的任一角色命中即放行 |
| 失败 | 拒绝返回 `PERMISSION_DENIED`；判定过程出错同样拒绝 |

**未登记路径必须拒绝**：这是授权系统的默认值。若默认放行，新增一个忘记登记的接口就等于自动对所有人开放，且不会有任何告警。

**认证与授权分离**：认证回答「你是谁」，授权回答「你能做什么」；失败语义分别是 `UNAUTHENTICATED` 与 `PERMISSION_DENIED`。合并会让客户端无法区分「重新登录」与「权限不足」。

**读者端不做 RBAC**：内容对所有读者一视同仁，读者链路只做认证，不引入角色判定。

## 三、缓存与失效

授权判定的成本由两部分组成：用户的角色集合、角色到接口资源的映射。两者分别缓存。

| 缓存 | 位置 | 内容 | 失效 |
|---|---|---|---|
| 用户角色 | 进程内存 + Redis | `user → roles` | 用户级失效广播 + 代际号 + TTL |
| 权限策略 | 进程内存 | `role → 接口资源` 快照 | 策略失效广播，整体重载 |

**为什么按用户缓存角色，而不是按角色缓存接口集合**：角色数量少，但角色到资源的映射需要与策略快照一起原子替换；按用户缓存角色集合，命中后在本进程内完成匹配，判定路径零远程调用。

**代际号解决「在途加载写回旧值」**：

```
读请求读到旧角色 ──▶ 管理员撤销权限，递增代际 ──▶ 读请求写回缓存
                                                    │
                                        代际已变，写回被丢弃
```

只删缓存挡不住在途请求：它可能已经拿到旧角色，并在删除之后写回。因此失效必须同时递增代际号——读侧只接受代际一致的缓存，写侧只在代际未变时写入。

**失效广播只做加速**：Pub/Sub 会丢、消费者会漏。正确性由两个上界保证：用户角色缓存的 TTL（5 分钟）、策略快照的重载周期（60–120 秒轮询兜底）。广播丢失时，最坏情况是等待对应上界到期。

**本地缓存的最大年龄不得超过上游 TTL**：否则进程内副本会永久遮蔽 Redis 的过期，撤权在本地永远不生效。

## 四、时效

权限变更按后果分两条通道：

| 变更 | 通道 | 典型时效 | 保证上界 |
|---|---|---|---|
| **身份吊销**：停用、注销、强制下线、改密 | 会话撤销（令牌失效） | 下一次请求 | 立即，无陈旧 |
| **权限收紧**：移除用户角色、角色定义收紧 | 用户角色失效 + 策略失效 | 毫秒级（广播到达） | **5 分钟**（TTL 兜底） |
| **菜单可见性** | 策略失效 | 毫秒级 | 5 分钟 |

**长连接不适用「下一次请求」**：它由吊销事件通道主动断开；事件丢失时，在下一次业务动作前校验会话，见《实时通信》D6。

**为什么吊销与权限变更分开**：

- 吊销是「身份不能用了」，必须立即生效；它操作的是单个会话或主体级的键，扇出小，可以做到无陈旧。
- 权限变更是「身份还能用，但权力变了」，影响的是角色集合与策略快照；广播通常即时到达，但必须有一个可证明的兜底上界。

**5 分钟是承诺，不是平均值。** 它来自用户角色缓存的 TTL：即使所有广播都丢失，一个已被撤销的角色最多再存活 5 分钟。把上界写出来，评审才能判断这个窗口是否可以接受；写「立即生效」而实际依赖 TTL，是在把时效交给运气。

**权限变更不得触发下线。** 降级角色、收紧角色定义只影响下一次判定，不关闭会话、不撤销令牌。只有身份类事件才走吊销通道。

**长连接必须显式处理**：STOMP 连接建立后，HTTP 侧的中间件覆盖不到它。权限收紧后，长连接上的下一次业务动作仍须重新判定；身份吊销则必须由长连接侧主动断开或拒绝后续帧。具体机制见《实时通信》。

## 五、变更入口唯一

权限失效的可靠性取决于**变更入口是否唯一**。有多处能改权限，就有多处会漏失效。

| 变更 | 唯一入口 |
|---|---|
| 角色、菜单、接口资源 | `access` 模块的写接口 |
| 用户-角色关系 | `access` 模块的分配接口 |
| 接口资源清单 | 从路由表同步，不手工维护 |

**接口资源从路由表同步**：新增路由后执行同步，登记方法与路径；同步是幂等的，可重复执行。手工维护接口资源清单迟早会与路由漂移，而漂移的后果是「接口存在但无人能授权」或「路径写错导致未登记拒绝」。

**失效与写操作同事务边界**：写操作提交后再发失效广播；广播失败不回滚写操作，但有 TTL 兜底。广播必须在事务提交后发出 —— 事务未提交就广播，其他实例可能回源读到旧值并写回缓存。

## 六、关键决策

### D1 两类资源，接口资源是唯一服务端裁决依据

- **约束**：菜单需要下发前端，接口需要服务端判定；两者粒度不同。
- **备选**：菜单即权限；或只做接口权限。
- **选择**：两类资源独立存储，服务端只认接口资源。
- **代价**：同一角色需要维护两套授权关系。
- **重审触发**：菜单与接口的授权关系长期完全一致，维护成本超过收益。

### D2 未登记路径默认拒绝

- **约束**：新增接口若默认放行，等于自动公开。
- **备选**：未登记默认放行；或只在开发环境告警。
- **选择**：拒绝，并记录日志。
- **代价**：新增接口必须同步登记，否则不可用。
- **重审触发**：出现无法从路由表生成资源清单的动态路由。

### D3 按用户缓存角色，策略快照驻留进程

- **约束**：判定在每请求路径上，不能每次都查库。
- **备选**：按角色缓存接口集合；或每请求查库。
- **选择**：用户角色缓存 + 进程内策略快照。
- **代价**：失效需要同时覆盖用户与策略两条链路。
- **重审触发**：角色数量或策略规模增长到进程内存不可承受。

### D4 失效广播只做加速，TTL 给上界

- **约束**：广播不可靠；必须有可证明的兜底。
- **备选**：只靠广播；或只靠 TTL。
- **选择**：广播加速；TTL 给出 5 分钟上界。
- **代价**：最坏情况下权限变更 5 分钟后才生效。
- **重审触发**：业务要求比 5 分钟更短的上界，且能承担更高的失效成本。

### D5 吊销与权限变更分两条通道

- **约束**：身份失效必须立即；权限变更可以接受有界陈旧。
- **备选**：统一一条通道；或都走会话撤销。
- **选择**：吊销走会话撤销；权限变更走缓存失效。
- **代价**：两套机制、两套测试。
- **重审触发**：出现无法用「身份 / 权限」二分表达的变更。

### D6 权限变更入口唯一

- **约束**：多个入口意味着多处漏失效。
- **备选**：各模块自行修改授权关系。
- **选择**：只有 `access` 模块能写角色、资源与分配关系。
- **代价**：其他模块需要变更权限时，必须调用 access。
- **重审触发**：出现必须由其他模块自治的授权域。

### D7 判定失败即拒绝

- **约束**：放行等于在故障时打开越权通道。
- **备选**：缓存不可用时放行；或只读请求放行。
- **选择**：策略或角色查询失败一律拒绝。
- **代价**：Redis / 数据库故障时管理端不可用。
- **重审触发**：出现比拒绝更安全的降级路径。

## 七、不变量

- [ ] 服务端只依据接口资源判定；菜单不参与准入。
- [ ] 未登记的路径一律拒绝。
- [ ] 用户角色缓存带代际号；失效时递增，旧代际的写回被丢弃。
- [ ] 本地缓存最大年龄不超过上游 TTL。
- [ ] 失效广播只做加速；TTL 给出可证明的上界。
- [ ] 权限变更不撤销令牌、不下线；身份吊销才走会话撤销。
- [ ] 权限变更入口唯一，且失效在事务提交后发出。
- [ ] 判定过程出错时拒绝，不放行。
- [ ] 接口资源清单从路由表同步，不手工维护。

## 八、失败与降级

| 情形 | 行为 | 用户可见后果 |
|---|---|---|
| 策略快照加载失败 | 拒绝 | 管理端接口不可用 |
| 用户角色缓存未命中 | 回源查询 | 延迟上升 |
| 回源失败 | 拒绝 | 管理端接口不可用 |
| 失效广播丢失 | TTL 到期后生效 | 权限变更延迟，最长 5 分钟 |
| 路径未登记 | 拒绝 | 接口不可用，需同步资源 |
| root 角色 | 放行 | 超级管理员可访问全部接口 |
| 长连接上的权限变更 | 下一次业务动作重新判定 | 不立即断开；身份吊销另行处理 |

## 九、边界与重新审视

- **不做**：ABAC、行级权限、多租户、跨系统权限联邦。
- **重新审视**：出现按数据行授权的需求；权限变更要求秒级以内的硬上界；长连接需要实时撤销而不只是下一次动作判定。
