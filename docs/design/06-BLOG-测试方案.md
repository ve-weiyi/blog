# blog 博客系统 — 测试方案

初稿：2026-09-11　·　最近更新：2026-09-16

## 一、测试分层

### 1.1 分层模型

| 层 | 对象 | 依赖 | 目的 |
|---|---|---|---|
| **单元测试** | 纯逻辑：算法、解析、转换、校验 | 无外部依赖 | 快速验证正确性，重构的护栏 |
| **生成物测试** | 代码生成工具（`goctlx`）从契约产出的骨架与类型 | 无 | 保证生成结果符合预期 |
| **接口测试** | 服务的对外接口（gRPC / HTTP） | 服务自身真实启动；**外部依赖全部桩化** | 保证**实现遵守契约**——形状、类型、必填、错误码 |
| **集成测试** | 服务 + 真实数据库/缓存 | 真实依赖（数据库 / 缓存用容器实例） | 验证数据访问与事务语义 |
| **端到端** | 前端 + 网关 + 服务 | 完整链路 | 验证关键用户路径 |

**分层原则**：下层**快而广**，上层**慢而准**。不追求每层都覆盖全部代码——单元测试管逻辑密度高的地方，生成物与接口测试管契约边界，集成测试管数据语义，端到端只管少数关键路径。

### 1.2 各层职责

**单元测试**优先覆盖：

- **无外部依赖的纯函数**——工具库、编解码、格式化、规则判定
- **状态机与生命周期逻辑**——状态流转、幂等键生成
- **边界条件**——分页边界、空值、超长输入

**生成物测试与接口测试是两件不同的事**，此前被混为一谈，此处拆开：

- **生成物测试**测的是 `goctlx` **从契约产出代码**这一步：生成的骨架与类型是否与契约一致。若不符，属于**生成工具的问题而非业务问题**。它测「生成结果符合预期」，而非逐字段断言。
- **接口测试**测的是**实现是否遵守契约**：起真实服务，按契约调用，断言请求 / 响应形状与错误码。**这一层此前缺失**——生成物正确不代表业务实现用了生成的骨架，也不代表语义正确。它**不验证业务规则**（那是单元测试与集成测试的职责），只验证**契约边界**：字段有无、类型、必填、错误码取值。

**分发出口同属对外契约**——RSS / sitemap / robots.txt 的格式由 `protocol` 定义（见《01》§2.5），因此也纳入本层：断言可被标准解析器解析、结构与必填项齐全，以及**只含「已发布 + 公开」的内容**（《01》§2.2 的单一谓词在分发侧同样生效）。

**集成测试**优先覆盖：

- **事务边界**——跨表写入的原子性（如内容发布同时写文章与标签关联）
- **查询正确性**——关联查询、分页、软删除过滤

**端到端**优先覆盖少数关键路径（读者登录 → 浏览 → 互动；管理员登录 → 发布内容 → 审核互动），不做全量界面覆盖。

### 1.3 覆盖策略

测试投资按**接口稳定性**分配，而非按代码量平均：

- **公共库优先**——被所有服务复用的能力，接口稳定，测试回报最高
- **接口测试次之**——每个服务的接口面固定、断言机械，是**契约漂移最有效的护栏**；它恰好填在单元测试（无依赖但看不到契约）与端到端（覆盖契约但成本高）之间的空档
- **业务服务的纯逻辑**——状态流转、规则判定、权限语义，无外部依赖、编写成本低、回归价值高
- **集成测试有选择性**——成本较高，只覆盖确实存在多表写入的场景
- **端到端最后做**——成本最高，只覆盖关键路径

**明确不做**：追求覆盖率数字。覆盖率是结果而非目标，无差别覆盖会产出大量低价值断言。

## 二、外部依赖的处理

| 依赖 | 策略 |
|---|---|
| 数据库 | 集成测试用真实实例；单元测试不触碰 |
| 缓存 | 同上 |
| 外部服务（邮件 / 短信 / 第三方 OAuth） | **接口抽象 + 桩实现**，测试注入桩 |
| 文件存储 | 同上（存储适配器可切本地实现） |
| 时钟 | 涉及过期判定的逻辑，通过注入时间源而非直接取当前时间 |

**设计约束**：**外部依赖必须经接口注入**，而非在业务代码内直接构造。这既是可测试性的要求，也是依赖显式注入原则的体现——测试能否注入桩，取决于生产代码是否容许注入。

## 三、执行与门禁

测试的价值取决于**失败时是否阻断**。分层与覆盖策略之外，还须定义执行时机：

| 时机 | 范围 | 失败后果 |
|---|---|---|
| 提交前（本地） | 单元测试、生成物测试 | 开发者自行判断 |
| 流水线构建前 | 该服务的单元测试、生成物测试、接口测试 | **阻断该服务的镜像构建与推送** |
| 部署后 | 健康验证（见《05》§3.3） | 阻断该次部署 |
| 定期 / 发布前 | 集成测试、端到端 | 阻断该次发布 |

**两条约束**：

- **接口测试属于构建门禁**，不是可选的周期性任务——契约漂移只有在每次构建时校验才拦得住
- **集成测试与端到端不进每次构建**——它们依赖真实环境且耗时，进每次构建会拖慢反馈、并让门禁因环境问题误报。二者按发布节奏执行
