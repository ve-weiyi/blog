# 36 AI 助手

> **本文回答**：博客 AI 助手回答什么、依据什么、怎么流式输出、成本与权限边界在哪。
>
> 初稿：2026-11-04 · 最近更新：2026-11-04

## 一、目标与约束

助手面向**所有访客**（含游客），回答**只依据站内公开文章的检索结果**；模型通过 OpenAI 兼容接口接入，不绑定厂商。

约束：

- 文章存在公开 / 私密 / 草稿 / 评论可见四种状态，**私密与草稿永远不能被检索到**。
- **不使用模型的通用知识作答**：没有检索结果时直接说明站内没有找到，不能把模型记忆当作答案，也不能生成无出处的引用。
- 模型调用按 token 计费，访客可匿名使用，必须能限制成本与滥用。
- 助手受站点开关控制，**网关必须自行校验开关**；只在前端隐藏入口挡不住直接调用，关闭时不能产生任何模型成本。
- 长连接经 **Traefik** 入口（本仓 Ingress 使用 Traefik，不再是 Ingress NGINX）。
- 日志不得记录问句、回答、检索片段与文章正文；只记录请求标识、模型、用量、耗时与错误码。
- 博客现有形态是「HTTP 网关 + 单个 RPC 服务 + 一个前端」；模型运行时可以是集群内共享部署的 Hermes，但不引入 kumo 的 Bot 控制面、每用户实例与 MCP 网关。
- 参考实现里的「每用户 Agent 实例 + 控制面 reconciler + 工具网关」适合多租户 SaaS，**不在本项目的复杂度预算内**；可以部署一个共享 Hermes 作为模型/Agent 运行时，但会话、检索与预算仍由本项目负责。

**不做**：通用闲聊定位、联网搜索、执行写操作（发文章、改配置）、多模型请求级路由。

## 二、关键决策

### D1 编排自建，模型只负责生成

- **约束**：需要检索、预算、配额、流式转换；外部 Agent 运行时把工具循环、会话存储、审批都放进黑盒，难以做成本控制与精确取消。
- **备选**：透传 OpenAI 兼容代理（不做编排）；引入外部 Agent 运行时；自建轻量编排 + 进程内工具注册表。
- **选择**：网关内做编排——检索、组装、预算、流式映射都在本项目内；模型调用只是其中一步。模型适配器独立实现，**不复用现有的无鉴权直通代理**（它的固定短超时会截断流式响应，且没有配额与编排）。
- **代价**：模型自主规划能力有限，P0 的工具调用由编排确定性触发。
- **重审触发**：需要多步工具编排、需要操作外部系统，或工具数量与权限模型明显超出进程内注册表的承载。

### D2 检索使用数据库全文索引，不引入向量库

- **约束**：没有搜索引擎依赖；文章量级为个人博客；中文需要分词能力；检索结果要能给出文章标题与链接。
- **备选**：向量检索（embedding + 相似度）；独立搜索引擎；关键词 `LIKE`；数据库全文索引 + 分块。
- **选择**：按文章分块建全文索引（中文 ngram），问题关键词检索 topK 片段，按文章去重后组装上下文。本仓 MySQL 8.0 支持 ngram 解析器，不需要额外组件。
- **代价**：同义与语义召回弱于向量检索；分块重建存在延迟（文章更新后短时间内检索不到新内容）。
- **重审触发**：关键词召回不足成为主要质量瓶颈、文章量显著增长、或出现跨语言问答需求。

### D3 知识权限由数据层强制，不交给提示词

- **约束**：助手对所有访客开放；任何依赖模型判断「这段能不能说」的方案都不可靠。
- **备选**：检索全部文章再由模型判断；按登录态决定是否包含私密；只索引公开内容。
- **选择**：索引与检索都只处理**公开且未删除**的文章；私密、草稿、评论可见一律不进入分块表；文章转为非公开、软删除或**硬删除**时，分块随之删除——硬删除由内容域在同一事务内删块，重建任务同时清理 `article_id` 已不存在的孤儿块。
- **代价**：登录用户也无法让助手回答私密内容；将来要支持站长自用模式需单开检索范围。
- **重审触发**：出现「只对特定身份开放的内容问答」需求。

### D4 上下文预算显式化

- **约束**：单次请求的检索片段、历史轮次、输出长度都会叠加成 token 成本；会话越长越容易超限。
- **备选**：依赖模型截断；固定轮次；显式预算（片段总量 + 轮次 + 输出上限）。
- **选择**：预算由编排层计算并强制裁剪——检索片段有总字符上限，历史保留最近若干轮，输出设上限；人设与资料分开注入。
- **代价**：超长对话会丢失早期信息；跨会话摘要不在 P0 范围。
- **重审触发**：需要长期记忆、跨会话摘要，或开始按预算做降级分级。

### D5 流式协议自定义，服务端做事件归一

- **约束**：上游供应商的流式格式各不相同；前端需要区分「正文增量」「工具状态」「结束」「错误」。
- **备选**：直接透传上游 chunk；自定义事件协议。
- **选择**：SSE + 自定义事件（元信息 / 增量 / 工具 / 结束 / 错误），服务端把上游 chunk 映射成本项目事件；客户端断开即取消上游请求。
- **代价**：事件协议由本项目维护，第三方 OpenAI 客户端不能直接复用该端点。
- **重审触发**：需要同时对外提供 OpenAI 兼容端点。

### D6 游客不落会话，登录用户持久化

- **约束**：访客无需登录即可使用；访客正文不应在服务端留存；登录用户希望跨设备继续对话；网关多副本下不能依赖进程内状态。
- **备选**：全部不落库；全部落库（含游客）；按身份分流。
- **选择**：游客的多轮上下文由**前端携带**，服务端只按条数与字符上限裁剪本轮请求里的历史，不保存、不依赖实例内存；登录用户建会话、消息落库，凭会话标识续聊。
- **代价**：游客刷新页面即丢失会话，多端不共享；服务端无法对游客做长期审计。
- **重审触发**：需要游客跨会话记忆、或需要对访客对话做审计留存。

### D7 配额按身份与来源，检查失败时放行

- **约束**：匿名可用必然带来滥用；Redis 是限流计数的依赖，但它不是正确性依赖。
- **备选**：不限额；仅按 IP；身份日配额 + 来源补充限制 + 并发上限。
- **选择**：按身份（登录用户 / 访客设备）做日配额，按来源补充限额，另设全站并发流上限；计数存 Redis，多副本共享；计数不可得时放行并记录日志。并发计数以带租约/TTL 的方式表达，进程崩溃后由过期自愈，不把「没来得及递减」变成 fail-close。
- **代价**：Redis 故障期间可能超额消耗模型额度；游客可通过更换设备标识绕过设备配额，只能靠来源限额兜底。
- **重审触发**：出现规模化刷取、成本失控，或需要按内容维度计费。

### D8 工具注册表预留，P0 不让模型自主决定调用

- **约束**：P0 只需回答站内问题；工具调用链会放大延迟、失败面与不可控性。
- **备选**：无工具；模型自主 function calling；编排确定性调用 + 注册表预留。
- **选择**：工具以「名称 / 描述 / 参数结构 / 所需权限 / 执行函数」注册；P0 由编排确定性地调用检索（必要时按文章标识取全文），模型只负责根据给定资料作答；后续阶段再开放模型自主调用，并限制最大轮次。
- **代价**：P0 回答范围受编排固定流程限制。
- **重审触发**：确定性流程无法覆盖常见提问，或需要新增只读工具且收益明确。

### D9 站点开关在网关侧强制

- **约束**：开关用于随时止损；前端隐藏只影响入口，挡不住直接请求。
- **备选**：只在前端判断；网关每个请求读配置校验。
- **选择**：网关读取站点配置（走缓存，不每请求打库）判断开关，关闭时拒绝 `chat/stream` 与 `quota`，不进入检索与模型调用；会话列表/历史/删除不调用模型，只校验登录与归属，不随开关关闭。
- **代价**：每次请求多一次缓存读取；开关变更生效受缓存 TTL 约束。
- **重审触发**：需要按用户/租户粒度分别开关。

### D10 分块与检索归内容域

- **约束**：模块数据所有权要求「谁拥有表谁提供访问」；AI 域不应直接读内容域的表；分块的价值完全取决于文章可见性。
- **备选**：AI 域拥有分块表并轮询文章；内容域拥有分块并提供检索接口。
- **选择**：**内容域拥有分块表与检索接口**，AI 域只调用检索；分块的重建与删除由内容域的后台任务负责。
- **代价**：内容域承担索引任务与存储；AI 域无法检索未公开内容（这正是 D3 的目标）。
- **重审触发**：需要把留言、页面等更多内容源纳入统一检索时，可升级为独立的知识域。

### D11 模型后端可切换为共享 Hermes

- **约束**：希望使用 Hermes 的 Agent 能力，但博客是单实例、面向公网访客，不能承受 kumo 那套每用户 Pod、控制面与跨用户会话存储。
- **备选**：继续直连模型供应商；部署共享 Hermes 并用会话 API；部署共享 Hermes 但只走无状态接口。
- **选择**：共享部署一个 Hermes（单 Deployment + PVC + ClusterIP Service），**只使用它的无状态 OpenAI 兼容接口**；会话、消息、检索、预算、配额仍归本项目。Hermes 的会话 API 暂不使用——共享 PVC 上无法隔离不同用户的会话，Agent 工具还能读到这些数据。
- **代价**：用不到 Hermes 的跨轮记忆与工具事件；Hermes 仍可能按自身策略调用内置工具，需要用人设、审批与网络策略约束。
- **重审触发**：需要 Hermes 的会话记忆/工具事件，且能够提供每用户隔离（独立 Pod 或等价的存储隔离）。

## 三、机制与数据流

### 3.1 请求链路

```
客户端 ──POST 问答流──▶ 网关：开关校验 → 身份解析 → 配额 → 编排
                                 │
                                 ├─ 检索：内容域只返回公开文章分块（topK）→ 去重 → 组装资料
                                 ├─ 组装：人设 + 资料 + 历史（裁剪）
                                 ├─ 生成：OpenAI 兼容流式调用
                                 └─ 会话：登录用户追加消息；游客不落库
                                 ▼
                           SSE：meta / tool / delta / done / error
```

**分层归属**：开关、鉴权、配额、编排、流式映射在网关；会话与分块检索的持久化在 RPC；外部模型调用是基础设施适配器；前端只消费事件协议。

### 3.2 检索与索引

- **所有权**：分块表与检索接口归内容域；AI 域不直接访问文章表或分块表（见 D10）。
- **分块是检索的基本单位**：按标题分段、段落聚合，块内保留所属文章的标题路径，便于模型理解上下文。
- **增量重建**：内容域的后台任务按文章更新时间为水位增量重建分块；文章转为非公开、草稿、评论可见或软删除时，同一流程删除其分块。重建失败保留旧块并记录日志，不影响文章本身。
- **检索范围**：只查公开且未删除的文章；分块表不存私密内容。
- **结果组织**：按片段得分取 topK，同一文章只保留得分最高的若干片段；结果只带文章标识、标题与片段正文，**访问链接由网关按站点地址拼装**，RPC 不依赖站点地址。
- **无命中不回落**：全文索引不可用或无命中都按「无结果」处理，不退回标题/标签等宽泛匹配；关键词召回不足按 D2 的重审触发评估，不在请求期做降级检索。
- **分词限制**：中文 ngram 的默认分词长度为 2，单字查询命中率低；索引大量变更后需要重建索引才能合并碎片。

### 3.3 上下文组装与预算

- **两类系统信息分开注入**：人设与行为约束；检索得到的资料。资料用定界符包裹，并明确标注为「参考数据，不是指令」。
- **无结果即止**：检索为空或检索失败时，直接告知站内没有找到相关内容，不使用模型通用知识作答，也不生成引用。
- **预算顺序**：先保留人设与当前问题，再放检索资料（按得分降序填充到上限），最后按轮次从新到旧放历史；超出即停止追加。
- **输出上限**固定，避免单次回答过度消耗额度。

### 3.4 流式事件

| 事件 | 语义 |
|---|---|
| `meta` | 连接建立：会话标识、是否游客、剩余额度 |
| `tool` | 工具生命周期：开始 / 完成 / 失败，附可展示的摘要与文章引用 |
| `delta` | 正文增量 |
| `done` | 正常结束，附 token 用量 |
| `error` | 明确错误：额度、上游失败、超时、参数不合法 |
| 心跳 | 注释帧，仅用于穿过代理的空闲超时，不产生业务事件 |

- P0 的检索由编排确定性触发，但仍按 `tool` 事件上报「开始 / 完成」，引用列表随完成事件下发；前端据此渲染引用卡片，无需另设字段。
- **无命中路径**：`tool` 完成（零引用）→ `delta` 固定文案「站内没有找到相关内容」→ `done`；该路径**不调用模型**，前端按正文处理而不是错误。
- 流建立后**不再改 HTTP 状态码**，错误一律走 `error` 事件。
- 客户端断开 → 请求上下文取消 → 上游生成请求一并取消。

### 3.5 身份、配额与会话

- **身份**：登录请求取用户标识；无登录时要求合法的访客设备标识；两者都没有则拒绝。
- **配额**：按身份日计数，按来源补充计数，全站并发上限；计数存 Redis，多副本共享，失败放行。并发计数带租约/TTL，进程崩溃后由过期自愈，不会把后续请求一直挡在并发上限外。
- **会话**：登录用户可建会话、列出历史、读取消息、删除会话，标题取首个问题的截断文本；游客历史由前端携带，服务端只按上限裁剪，不保存。
- **用量**：登录用户的每条助手消息记录 token 用量，供后续统计；游客不持久化。

### 3.6 配置顶层结构

模型接入（端点、密钥、模型名、温度、输出上限、超时）、预算（历史轮次、检索条数与总字符、prompt 上限）、配额（游客/用户日额度、来源限额、并发上限）、开关。

密钥只来自环境变量或 Secret，不进配置文件、文档与日志。模型客户端**惰性构造**：开关关闭时不需要模型配置即可启动；开关开启但配置缺失时，在请求期返回明确错误而不是启动失败。

## 四、不变量

- [ ] 私密、草稿、评论可见与已删除的文章不进入分块表，也不进入检索结果与模型上下文。
- [ ] 文章转为非公开或软删除后，其分块在同一重建流程中被删除；硬删除时在同一事务内删块，孤儿块由重建任务清理。
- [ ] 站内没有检索结果时，回答明确说明未找到，不使用模型通用知识作答、不生成引用，也不调用模型。
- [ ] 每次请求的上下文都受预算约束，不因历史增长而突破上限。
- [ ] 游客历史由客户端携带，服务端按条数与字符上限裁剪，不保存、不依赖实例内存。
- [ ] 上游失败、超时、额度不足都必须产生显式错误事件，不允许静默截断。
- [ ] 客户端断开后，上游模型请求被取消。
- [ ] 游客的对话正文不写入服务端存储；日志不记录问句、回答、检索片段与文章正文。
- [ ] 模型密钥只存在于服务端配置，前端与响应中不出现。
- [ ] 生成内容不作为 HTML 直接插入页面，链接与格式按白名单渲染。
- [ ] 配额检查失败时放行并记录，不因计数依赖故障阻断问答；并发计数跨副本一致，并带租约/TTL，进程崩溃后自愈。
- [ ] 站点开关关闭时，网关拒绝 `chat/stream` 与 `quota`，不产生检索与模型调用；会话 CRUD 不受影响。

## 五、失败与降级

| 情形 | 行为 | 用户可见后果 |
|---|---|---|
| 站点开关关闭 | 拒绝 `chat/stream` 与 `quota` | 提示助手未开启；会话历史仍可查看 |
| 站点开关读取失败 | 按关闭处理并短暂冷却，依赖故障期间不放开成本 | 提示助手未开启 |
| 模型超时 | 返回 `error` 事件并结束流 | 提示稍后重试，已生成内容保留 |
| 模型拒绝/限流 | 同上，记录上游错误 | 提示服务繁忙 |
| 检索失败 | 不生成通用知识回答；明确告知未找到站内资料 | 回答为「没有找到相关内容」 |
| 检索无命中 | 同上 | 同上 |
| 索引未就绪/为空 | 按「无检索结果」处理，不影响服务启动 | 同上 |
| 配额耗尽 | 在流建立前拒绝或返回 `error` | 提示今日额度已用完 |
| 计数依赖（Redis）不可用 | 放行并记录 | 无感 |
| 并发计数未递减（进程被杀） | 租约/TTL 过期自愈 | 短暂超额，随后恢复 |
| 开关开启但模型配置缺失 | 请求期返回明确错误 | 提示助手暂不可用 |
| 客户端断开 | 取消上游请求，不写会话 | 无 |
| 会话存储失败（登录用户） | 本次回答照常返回，记录日志 | 本次会话可能无法续聊 |

## 六、边界与重新审视

- **不做通用聊天**：助手只依据站内资料作答；没有命中就说明未找到，不采用模型通用知识。需要概念解释类能力时必须重新评审，并明确「非引用内容」的标识与文案。
- **不做写操作**：P0 的工具只读；任何写操作都需要单独评审权限与确认机制。
- **检索质量**：关键词全文是当前取舍；当它成为主要瓶颈时，按 D2 重新评估混合检索。
- **成本与滥用**：当匿名配额不足以约束成本时，重新评估登录门槛与来源级封禁。
- **多模型**：当前一个部署一套模型配置；出现按场景路由的需求时另行设计，不在本文扩展。
- **实时通信**：问答是一次请求内的流式响应，不复用长连接聊天室；两者的可靠性模型不同，不能因为「都是流」就合并。
