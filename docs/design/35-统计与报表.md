# 35 统计与报表

> **本文回答**：系统提供哪些统计、每个指标的口径是什么、数据从哪里来、允许旧多久。
>
> 初稿：2026-10-22 · 最近更新：2026-10-22

## 一、定位

统计面向管理端，提供四类报表：

| 报表 | 内容 |
|---|---|
| 仪表盘 | 用户数、文章数、留言数、今日 UV / PV、环比 |
| 内容统计 | 文章总数、分类分布、标签分布 |
| 访问趋势 | 按日期的 UV / PV / 累计值 |
| 地域分布 | 用户与访客的来源地区聚合 |

**统计只用于展示与分析，不参与任何业务判定。** 准入、配额、排序、推荐都不得读取统计结果 —— 它允许旧，而业务判定不允许。

## 二、指标口径

口径必须写死，否则同一个「活跃用户」在不同报表里会得出不同数字。

| 指标 | 口径 | 数据来源 |
|---|---|---|
| 总用户数 | 非物理删除的用户总数 | 用户表 |
| 新增用户 | 按 `created_at` 落在当日的用户数 | 用户表 |
| 活跃用户 | 当日访问日志中**去重**的用户标识数 | 访问日志 |
| 总文章数 | 非删除的文章总数（含草稿 / 私密） | 内容表 |
| 总留言数 | 非删除的留言总数 | 讨论表 |
| 今日 UV | 当日去重访客数 | Redis 日计数 |
| 今日 PV | 当日页面浏览数 | Redis 日计数 |
| 累计 UV / PV | 历史日快照的累计值 | 日快照表 |
| 分类 / 标签分布 | 每个分类 / 标签下的文章数 | 内容表与关联表 |
| 地域分布 | 按来源地区聚合的用户 / 访客数 | 用户 / 访客的来源地区字段 |
| 环比 | （今日 − 昨日）/ 昨日 | 今日实时值 + 昨日快照 |

**分母为零时返回 0，不返回除零结果或空值。** 新站点第一天的环比没有意义，显式给 0 比给一个 `NaN` 更容易被前端处理。

**「活跃」按访问日志去重，不按登录状态。** 匿名访问也是活跃；否则会低估读者端的真实规模。

**地域是粗粒度聚合**：只保留省 / 国家级别的来源描述，报表不出现原始 IP。原始 IP 只存在于访问日志与用户/访客记录中，按保留期清理。

## 三、数据流

```
当日实时 ──▶ Redis 日计数（UV / PV）
历史趋势 ──▶ 日快照表（t_daily_stats）
              ▲
              │ 每日任务：计算昨日 → 按日期幂等 upsert
```

| 时间范围 | 来源 | 说明 |
|---|---|---|
| 今日 | Redis 计数 + 实时查询 | 未落快照前以实时值为准 |
| 历史 | 日快照表 | 不再回查明细，避免趋势查询扫描大表 |
| 补数 | 重跑指定日期 | 幂等 upsert；不删除其他日期 |

**日快照是统计模块拥有的物化数据**，不是对业务表的实时投影。它的刷新周期就是历史数据的延迟上界：当天看不到昨天的快照，说明任务失败，而不是数据不存在。

**快照写入必须幂等**：同一日期重复计算只覆盖该日记录；失败时保留上一版，不写半条记录。

## 四、所有权与只读投影

统计模块拥有日快照表与聚合任务。它需要读取用户、访客、文章、分类、标签、留言、访问日志与 Redis 计数，这些数据分别属于其他模块。

因此统计是**唯一的只读报表投影例外**（见《模块与数据所有权》）：

- **可以只读**其他模块的表与 Redis 计数；
- **不得写**其他模块的表，不得参与对方事务；
- **不得被其他模块反向依赖** —— 业务逻辑读统计结果，就是把「允许旧」带进了判定链路；
- 该例外只适用于统计，不得被其他模块模仿。

**为什么允许这个例外**：为报表单独建一套跨域事件管道，在个人博客量级下成本远高于收益；只读查询不改变任何业务状态，风险可控。代价是统计与业务表结构耦合，表结构变更时必须同步检查报表查询。

## 五、性能

- 明细表按日期与用户标识建索引；趋势查询只读快照，不扫明细。
- 仪表盘的实时查询有超时；超时返回上次快照并标记「实时数据暂不可用」，而不是拖住页面。
- 地域聚合按来源地区字段分组；不对原始 IP 做逐条解析。
- 报表结果可以短缓存（秒级），但**缓存不得成为唯一数据源**：缓存失效时回源。

## 六、关键决策

### D1 统计是只读报表投影

- **约束**：报表需要跨域数据；为报表建事件管道成本过高。
- **备选**：通过各模块契约逐项取数；或允许统计只读跨域表。
- **选择**：只读跨域表与 Redis 计数，不写、不参与事务、不被反向依赖。
- **代价**：统计与业务表结构耦合；表结构变更要同步检查。
- **重审触发**：模块拆分到独立数据库；或统计查询开始影响业务库性能。

### D2 日快照 + 实时计数

- **约束**：趋势查询不能每次扫明细；当日数据又需要实时。
- **备选**：全部实时计算；或全部离线。
- **选择**：当日实时，历史读日快照；每日任务幂等落快照。
- **代价**：当天与历史的口径需要保持一致。
- **重审触发**：实时计数成本超过收益，或历史回溯要求更细粒度。

### D3 统计不参与业务判定

- **约束**：统计允许旧，业务判定不允许。
- **备选**：用统计做热门排序或配额。
- **选择**：只展示；判定回权威源。
- **代价**：热门排序需要另设离线口径。
- **重审触发**：出现必须实时按统计决策的业务。

### D4 刷新周期即延迟上界，补数幂等

- **约束**：历史数据必须有一个可证明的延迟上界。
- **备选**：不承诺延迟；或每次查询实时重算。
- **选择**：每日任务刷新；刷新周期即上界；补数按日期幂等 upsert。
- **代价**：当天与历史之间有一个刷新窗口。
- **重审触发**：业务要求分钟级报表。

### D5 地域粗粒度，报表不含原始 IP

- **约束**：原始 IP 是敏感数据；报表只需区域趋势。
- **备选**：报表展示原始 IP；或按城市聚合。
- **选择**：省 / 国家级别聚合；原始 IP 只留在源记录并按保留期清理。
- **代价**：无法从报表下钻到单个访客。
- **重审触发**：出现合规或运营要求的下钻场景，且能提供授权与审计。

### D6 固定报表，不引入查询语言

- **约束**：报表是固定视图；动态查询会带来注入与性能风险。
- **备选**：动态集合 + 过滤表达式；或固定报表。
- **选择**：固定报表与固定参数。
- **代价**：新增报表需要开发。
- **重审触发**：运营需要频繁自定义维度，且固定报表无法覆盖。

## 七、不变量

- [ ] 统计结果不参与准入、配额、排序或推荐。
- [ ] 每个指标的口径在本文有唯一定义，报表之间不各算一套。
- [ ] 历史趋势只读日快照，不扫描明细表。
- [ ] 日快照按日期幂等 upsert；失败不写半条记录。
- [ ] 统计只读其他模块的数据，不写、不参与事务、不被反向依赖。
- [ ] 报表不出现原始 IP；地域只到省 / 国家级别。
- [ ] 分母为零时返回 0。
- [ ] 实时查询超时返回可识别的降级结果，不拖住页面。

## 八、失败与降级

| 情形 | 行为 | 用户可见后果 |
|---|---|---|
| Redis 计数不可用 | 回退到日快照；无快照则返回 0 | 今日 UV / PV 可能为 0 或偏旧 |
| 日快照任务失败 | 保留上一版；告警；下次重跑 | 历史趋势缺少最新一天 |
| 明细表查询超时 | 返回上次快照并标记实时不可用 | 仪表盘部分指标延迟 |
| 地域字段缺失 | 归入「未知」 | 地域分布少一部分 |
| 补数失败 | 保留原记录；重试 | 指定日期数据不变 |

## 九、边界与重新审视

- **实时大屏**：当前是管理端报表，不做秒级刷新；需要时重新评审推送与缓存。
- **用户画像 / 行为分析**：当前只做聚合，不做个体追踪。
- **数据仓库**：当前不引入；报表查询开始影响业务库时再评估只读副本或离线导出。
- **保留期**：访问日志与日快照的保留期由部署策略决定；统计不应无限增长。
