# 31 媒体、站点与分发

> **本文回答**：图片等资产如何进入系统，站点如何组织，内容如何变成对外出口。
>
> 初稿：2026-10-22 · 最近更新：2026-10-22

## 一、媒体

### 1.1 模型

| 对象 | 关系 | 可见性 |
|---|---|---|
| 相册 | 包含照片 | 私密 / 公开 |
| 照片 | 属于一个相册 | **继承相册** |

照片不单独设可见性：同一相册里的照片对读者应保持一致；单独授权会让「这张能看、那张不能看」变成相册页面的常态，且每张照片都要多一次判定。

### 1.2 上传

```
客户端 ──▶ 申请上传凭据（服务端签发，短 TTL，限定键前缀）
              │
              ▼
         直传对象存储 ──▶ 返回存储键 ──▶ 业务接口只保存引用
```

**二进制不经过网关。** 网关中转会占用带宽与内存，且让大文件上传与普通 JSON 请求共享同一条超时与限流链路。存储适配器负责签名与直传，业务只依赖「存储键」这一抽象。

| 约定 | 内容 |
|---|---|
| 存储键 | 由服务端生成或规范化；客户端文件名只作显示名 |
| 凭据 TTL | 短寿命，限定前缀与操作 |
| 大小与类型 | 服务端校验；不信任客户端声明的 `Content-Type` |
| 路径 | 规范化后拒绝 `../`、绝对路径与保留名 |
| 读取 | 公开资源可直接访问；私有资源用带时效的签名 URL |

### 1.3 存储适配器

本地磁盘、MinIO、阿里云 OSS、腾讯云 COS、七牛 Kodo 通过同一接口接入；业务只依赖接口，不感知后端。切换后端不改变业务代码与存储键语义。

**只存原图。** 多规格与 WebP / AVIF 当前不做；若引入，采用**按需变换、参数进 URL**：参数变则 URL 变，天然免失效。预生成所有规格会在规格调整时留下大量孤儿文件，且存储成本随规格数线性增长。

### 1.4 删除与孤儿清理

| 动作 | 数据 | 对象存储 |
|---|---|---|
| 软删除相册 | 相册 `is_delete=1`，并**级联**其照片 | 保留 |
| 恢复相册 | 只恢复相册；**不反向恢复照片** | 保留 |
| 软删除照片 | 照片 `is_delete=1` | 保留 |
| 物理销毁相册 | 事务内删除相册与其照片行 | 异步清理 |
| 物理销毁照片 | 删除照片行 | 异步清理 |

**恢复不反向恢复照片**：照片可能在相册删除后又被单独删除过；一并复活会把用户已经放弃的内容重新暴露。

**数据库删除不等待对象存储**：一次删除请求不应因为对象存储超时而失败。数据库行先删或先标记，对象清理交给异步任务；任务失败可重试，重复执行幂等。

**孤儿清理按引用扫描，不按时间盲删**：对象键可能被文章封面、用户头像、站点配置、页面轮播、照片引用。清理任务先收集全部引用，再删除「不在引用集合且超过保留期」的对象。**绝不删除仍被引用的对象** —— 一次误删无法恢复。

## 二、站点

| 对象 | 内容 | 可见性 |
|---|---|---|
| 站点配置 | 站点名、描述、备案、社交链接等 | 公开 |
| 关于我 | 个人介绍、头像、社交链接 | 公开 |
| 自定义页面 | 页面名、标签、封面、轮播图 | 公开 |
| 友链 | 名称、地址、头像、描述 | 公开 |

- **站点配置是单例**：读多写少，读取可缓存；写入后递增站点版本号，缓存整体失效。
- **页面没有私密态**：需要隐藏的页面应删除，而不是加一个「私密页面」状态 —— 页面是站点结构的一部分，私密页面会让导航与 sitemap 出现空洞。
- **友链不自动抓取对方站点信息**：自动抓取是 SSRF 面，且对方页面结构不可控；名称、头像、描述由管理员填写。
- **友链是出站链接**：渲染时加 `rel="noopener noreferrer"`，不把对方内容嵌入本站。

## 三、分发

分发是博客区别于通用 CMS 的对外契约：它是订阅器与搜索引擎的入口，不是后台功能的附属产物。

| 出口 | 形态 | 约束 |
|---|---|---|
| **RSS 2.0** | XML | **必做**；最近 10–20 条；全文输出 |
| Atom | XML | 可选；强制唯一 ID 与 RFC 3339 时间，适合长期存档 |
| sitemap.xml | XML | 只输出 `<loc>` 与 `<lastmod>` |
| robots.txt | 文本 | 静态托管；`Sitemap:` 使用绝对 URL |

**为什么 RSS 必做**：它是全生态唯一无差别支持的订阅格式。个人博客没有广告变现，PV 的商业价值接近于零，订阅者才是核心资产；全文输出让订阅者不必回站即可阅读，这是有意选择的取舍。

**sitemap 只写 `loc` 与 `lastmod`**：搜索引擎明确忽略 `priority` 与 `changefreq`，写了是噪音。`lastmod` 必须对应**实质内容变更**，不能复用 `updated_at` —— 改标签、改状态都会让它变动，整站的日期信号随之失信。

**robots.txt 是唯一能按爬虫名选择性放行或屏蔽的地方**：AI 爬虫策略写在这里，不分散到应用中间件；`Sitemap:` 必须用绝对 URL，否则部分爬虫无法解析。

**出口只包含「已发布 + 公开」的内容。** 这与读者端可见性是同一个谓词，不允许为 feed 另写一套过滤条件 —— 漏写一处就是把草稿或私密内容推给所有订阅者。

**出口是生成物，不是存储。** 每次请求按当前内容生成，或在发布时刷新静态文件；无论哪种，格式与字段是契约，改动需要评审。

## 四、关键决策

### D1 照片继承相册可见性

- **约束**：相册是读者的浏览单位；逐张授权没有产品意义。
- **备选**：照片单独设可见性；或按相册 + 照片两级。
- **选择**：照片继承相册。
- **代价**：不能在同一相册里藏单张照片。
- **重审触发**：出现单张照片独立授权的需求。

### D2 上传凭据 + 直传

- **约束**：大文件不应经过网关；上传需要权限与路径约束。
- **备选**：网关中转；或客户端直接持有存储密钥。
- **选择**：服务端签发短 TTL 上传凭据，客户端直传。
- **代价**：依赖对象存储的可用性与客户端配合。
- **重审触发**：需要在入库前强制扫描或转码。

### D3 只存原图，派生图按需生成

- **约束**：预生成多规格会留下孤儿文件，规格调整成本高。
- **备选**：上传时生成全部规格；或只存原图。
- **选择**：只存原图；需要时按 URL 参数生成。
- **代价**：首次访问派生图有计算延迟，需要缓存。
- **重审触发**：派生图计算成为主要延迟来源。

### D4 分发只输出已发布 + 公开

- **约束**：feed 与 sitemap 是批量出口，泄漏面最大。
- **备选**：各出口自行过滤。
- **选择**：复用读者端单一谓词。
- **代价**：出口生成依赖内容模块的查询入口。
- **重审触发**：出现按渠道差异化的可见性需求。

### D5 `lastmod` 用实质变更时间

- **约束**：搜索引擎只在可验证时采用 `lastmod`。
- **备选**：复用 `updated_at`；或每次生成都用当前时间。
- **选择**：单独记录实质内容变更时间。
- **代价**：编辑流程需要区分「实质变更」与「元数据变更」。
- **重审触发**：内容模型无法区分两类变更。

### D6 友链不自动抓取

- **约束**：自动抓取是 SSRF 面，且对方页面不可控。
- **备选**：抓取标题、图标、描述。
- **选择**：管理员填写；渲染加 `noopener noreferrer`。
- **代价**：维护成本略高。
- **重审触发**：出现可信来源的批量导入。

### D7 软删除级联，恢复不反向

- **约束**：相册删除后其照片不应继续对读者可见；照片可能已被单独删除。
- **备选**：物理删除；或恢复相册时一并复活照片。
- **选择**：软删除相册时级联照片；恢复只恢复相册。
- **代价**：恢复后照片仍需单独恢复。
- **重审触发**：产品要求「恢复相册即完整恢复」。

### D8 对象清理异步、按引用扫描

- **约束**：对象存储可能超时；同一对象可能被文章、头像、站点配置等多处引用。
- **备选**：同步删除；或按时间盲删。
- **选择**：数据库先删或标记，对象清理异步；按引用集合删除超期且未被引用的对象。
- **代价**：需要清理任务与引用扫描；短期内存在孤儿对象。
- **重审触发**：对象数量增长到扫描成本过高，改用引用计数或对象生命周期策略。

## 五、不变量

- [ ] 二进制不经过网关，业务只保存存储键。
- [ ] 上传存储键由服务端生成或规范化；客户端文件名不参与路径。
- [ ] 照片可见性继承相册。
- [ ] 分发出口只包含已发布 + 公开内容，复用同一可见性谓词。
- [ ] `lastmod` 对应实质内容变更，不复用通用更新时间。
- [ ] sitemap 不输出 `priority` 与 `changefreq`。
- [ ] `robots.txt` 的 `Sitemap:` 使用绝对 URL。
- [ ] 友链渲染加 `noopener noreferrer`，不嵌入对方内容。
- [ ] 存储适配器可替换，业务不感知后端。
- [ ] 数据库删除不等待对象存储；对象清理异步且幂等。
- [ ] 恢复相册不反向恢复照片。
- [ ] 孤儿清理不删除仍被引用的对象。

## 六、失败与降级

| 情形 | 行为 | 用户可见后果 |
|---|---|---|
| 对象存储不可用 | 上传与派生图显式失败 | 媒体上传不可用；已存在引用按可用性返回 |
| 上传凭据过期 | 拒绝上传 | 重新申请 |
| 站点配置缓存不可用 | 回源 | 延迟上升 |
| 分发生成失败 | 返回错误或沿用上次静态产物 | 订阅器暂时拿不到更新 |
| 内容不可见 | 出口不包含该条 | 不会泄漏草稿或私密内容 |
| 友链地址不可达 | 不影响本站页面 | 外链打开失败由对方负责 |

## 七、边界与重新审视

- **订阅者与邮件订阅**：当前不存在。若引入，订阅者作为独立主体，退订凭据一次性、免登录；出口层只负责生成，不拥有订阅关系。
- **派生图**：当前不做；引入时按 D3。
- **CDN**：当前由反向代理承担；引入 CDN 时复用版本号失效，不改变出口格式。
- **多站点 / 多语言**：当前单站点；引入需要重新设计站点配置与分发路径。
