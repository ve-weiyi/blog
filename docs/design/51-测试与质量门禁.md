# 51 测试与质量门禁

> **本文回答**：哪些行为必须被测试锁住，测试放在哪一层，CI 拦什么。
>
> 初稿：2026-10-22 · 最近更新：2026-10-22

## 一、测试分层

| 层 | 对象 | 依赖 | 目的 |
|---|---|---|---|
| **单元测试** | 纯逻辑：算法、解析、转换、校验、状态机 | 无外部依赖 | 快速验证正确性，重构的护栏 |
| **生成物测试** | 代码生成工具从契约产出的骨架与类型 | 无 | 保证生成结果符合契约 |
| **接口 / 契约测试** | 服务的对外接口 | 服务自身启动；外部依赖桩化 | 保证**实现遵守契约**：形状、类型、必填、错误标识 |
| **集成测试** | 服务 + 真实数据库 / 缓存 | 容器实例 | 验证事务语义、查询条件、并发行为 |
| **端到端** | 前端 + 网关 + 服务 | 完整链路 | 验证少数关键用户路径 |

**分层原则**：下层快而广，上层慢而准。不追求每层覆盖全部代码——单元测试管逻辑密度高的地方，生成物与契约测试管边界，集成测试管数据语义，端到端只管关键路径。

**生成物测试与契约测试是两件事**：

- 生成物测试测「从契约生成代码」这一步；不符是**生成工具的问题**。
- 契约测试测「实现是否遵守契约」；生成物正确不代表业务实现用了生成的骨架。
- 两者都不能替代单元测试：契约测试不验证业务规则。

## 二、外部依赖

| 依赖 | 测试策略 |
|---|---|
| 数据库 | 单元测试用接口桩；集成测试用容器实例 |
| Redis | `miniredis` 或容器；不连生产实例 |
| 消息队列 | 接口桩；集成测试用临时实例 |
| 对象存储 | 接口桩；本地实现用于文件语义测试 |
| 外部 HTTP 服务 | 接口桩；不在测试中访问外网 |
| 时间 | 注入时钟（token / 会话过期测试不依赖 sleep） |

**测试中不使用真实凭据，不产生外部副作用。** 需要真实凭据、真实 SMTP、真实云厂商 AK 或会产生外部副作用的验证，升级为 `cmd/<名字>/main.go` 的人工诊断程序：

- 缺凭据时**显式失败**，打印缺哪个环境变量并退出；
- 禁止静默跳过或回落默认值；
- 产物写入 `runtime/`（已 gitignore）。

## 三、测试放置

- 优先把测试放在**不导入服务上下文（svc）的包**：`infra/`、适配器、纯函数、协议编解码。
- 导入 `svc` 会把整套 rpc client 与 proto 注册拉进测试二进制；同名 proto 重复注册可能直接 panic。需要 svc 的测试应隔离在独立包，或改用更小的依赖接口。
- 表驱动优先；一个用例一个断言目标；失败信息包含输入与期望。
- **不依赖固定端口、不依赖执行顺序、不 sleep 等异步**；需要等待时用轮询 + 超时，或注入时钟。
- 并发相关的包必须能被 `-race` 覆盖：连接、中继、缓存、限流、MQ 消费。

## 四、质量门禁

CI 对每个 Go 模块执行：

| 步骤 | 内容 | 失败即阻断 |
|---|---|---|
| `gofmt` | 未格式化文件 | 是 |
| `go build ./...` | workspace 构建 | 是 |
| `GOWORK=off go build ./...` | **单模块 standalone 构建** | 是 |
| `go vet ./...` | 静态检查 | 是 |
| `go test -short ./...` | 单元与不依赖环境的测试 | 是 |
| `go test -race -short ./...` | 并发密集模块 | 是 |

**standalone 构建是硬门禁**：workspace 会取全仓最高版本，恰好掩盖「模块自身声明的最低依赖版本不可用」这类问题。只跑 workspace 构建，等于放弃对依赖声明正确性的检查。

**前端门禁**：

- `pnpm install --frozen-lockfile`：lockfile 必须入库，CI 不接受锁文件漂移。
- `pnpm type-check`：类型错误阻断。
- 构建产物由发布流程负责，CI 只做类型检查。

**契约与错误表的自检**：

- 标识集合与 HTTP 映射表必须双向一致；新增标识未登记映射时测试失败。
- 标识与 gRPC canonical 对照必须双向一致。
- 生成物从干净工作区重新生成，不应产生额外差异。

## 五、覆盖策略

**按接口稳定性分配，不按代码行数平均**：

| 优先级 | 对象 | 理由 |
|---|---|---|
| 高 | 公共库、协议编解码、鉴权、限流、缓存失效 | 被所有服务复用，错误面最大 |
| 高 | 状态机：发布 / 撤回、审核、会话轮换 | 分支多，错误代价高 |
| 中 | 数据访问：事务、查询条件、分页边界 | 用集成测试覆盖 |
| 低 | 生成代码、路由表 | 由生成器与契约测试保证，不手写测试 |
| 低 | 薄 handler | 只做解析与转发，逻辑在 logic |

**设计文档里的「不变量」是测试目标**：每条可断言的不变量都应有对应用例，或在评审清单中说明为什么暂不可测。没有测试的不变量只是愿望。

**失败路径与降级路径必须覆盖**：缓存不可用、会话存储不可用、MQ 不可用、外部 API 超时——这些分支平时不执行，出问题时才执行，最需要测试。

## 六、关键决策

### D1 分层测试，契约与生成物分开

- **约束**：生成物正确不等于实现正确；实现正确不等于业务规则正确。
- **备选**：只做单元测试；或只做端到端。
- **选择**：五层分工，各管一件事。
- **代价**：需要维护多套测试基建。
- **重审触发**：某一层长期没有发现缺陷，且维护成本高于收益。

### D2 外部依赖按接口桩化，测试不连真实环境

- **约束**：真实依赖不可重复、可能产生副作用、需要凭据。
- **备选**：测试直连开发环境。
- **选择**：接口桩 + 容器实例；真实凭据只进人工诊断程序。
- **代价**：桩可能与真实实现漂移。
- **重审触发**：出现无法用接口桩表达的行为。

### D3 环境相关测试用 `-short` 显式跳过

- **约束**：CI 没有真实凭据与外网；静默跳过会让测试形同虚设。
- **备选**：测试自动检测环境并跳过；或全部放进 CI。
- **选择**：用 `testing.Short()` 守卫；CI 跑 `-short`。
- **代价**：本地需要主动跑完整测试。
- **重审触发**：CI 能提供所有依赖的容器。

### D4 测试尽量不导入 svc

- **约束**：svc 会拉入整套 rpc client 与 proto 注册，测试变重且可能 panic。
- **备选**：所有测试都通过 svc 构造。
- **选择**：优先测试不依赖 svc 的包；需要时隔离在独立包。
- **代价**：部分 logic 需要重构为可注入的小接口。
- **重审触发**：出现必须整体装配才能验证的行为。

### D5 standalone 构建是硬门禁

- **约束**：workspace 构建会掩盖模块自身依赖声明的问题。
- **备选**：只跑 workspace 构建。
- **选择**：每个模块额外跑 `GOWORK=off go build ./...`。
- **代价**：CI 时间增加。
- **重审触发**：模块不再独立发布。

### D6 不变量是测试目标

- **约束**：设计文档写了不变量，但没人验证，等于没写。
- **备选**：只按覆盖率驱动。
- **选择**：每条可断言的不变量对应测试或评审项。
- **代价**：需要维护不变量清单与用例的对应关系。
- **重审触发**：不变量数量增长到无法逐条维护，改为抽样。

## 七、不变量

- [ ] CI 必过 `gofmt`、`go build`、`GOWORK=off go build`、`go vet`、`go test -short`。
- [ ] 并发密集模块必过 `-race`。
- [ ] 前端 lockfile 入库，CI 使用 `--frozen-lockfile`。
- [ ] 错误标识与 HTTP 映射、gRPC canonical 对照双向一致。
- [ ] 测试不连接真实环境、不使用真实凭据、不访问外网。
- [ ] 环境相关测试用 `testing.Short()` 守卫，不静默跳过。
- [ ] 时间相关逻辑注入时钟，不依赖 sleep。
- [ ] 设计不变量有对应测试或评审项。
- [ ] 测试失败信息包含输入与期望。

## 八、失败与降级

| 情形 | 行为 | 约束 |
|---|---|---|
| 测试偶发失败 | 标记为不稳定并修复；不长期重试掩盖 | 连续失败必须定位 |
| 环境依赖缺失 | `-short` 跳过并说明原因 | 不得静默通过 |
| 生成物差异 | 阻断合并；修契约或生成器，不手改产物 | 生成物必须可重复 |
| 覆盖率下降 | 评审说明，不作为唯一硬门禁 | 关注关键路径而非总行数 |
| 前端 lockfile 漂移 | CI 失败 | 锁文件必须入库 |

## 九、边界与重新审视

- **不做**：以覆盖率百分比作为唯一门禁、UI 全量自动化、生产环境拨打真实外部服务。
- **重新审视**：测试运行时间超过可接受范围；出现必须端到端才能复现的缺陷；CI 能稳定提供所有依赖。
