> 定位：**实现计划，日期快照**。落地后代码与协议为唯一真相，本文不逐字追更。
> 依据：[《AI 助手》](../design/36-AI助手.md) 的决策 D1–D10。

## 一、现状与目标

**现状**

- 前端已有一套 `AiAssistant` 组件（悬浮球、面板、角色、流式渲染），但在 `App.vue` 中被注释掉，没有挂载；它直接 `fetch` 外部地址，SSE 解析没有跨 chunk 缓冲，正文用 `v-html` 渲染。
- vkit 里有一个 OpenAI 兼容直通代理：固定 10 秒的 HTTP 超时会截断流式响应，没有鉴权、检索与配额，**不作为对外入口**，也不作为本次实现的底座。
- protocol 与 blog-cloud 没有 AI 相关定义与实现；站点开关 `is_ai_assistant` 的存储与后台 UI 已就绪，但**后端没有任何读取点**。
- 网关已有成熟的 SSE 范式（通知流）、Redis 限流中间件与站点配置读取链路。
- 反向代理是 **Traefik**（Ingress 使用 `ingressClassName: traefik`），不是 Ingress NGINX。
- 数据库为 MySQL 8.0.34，InnoDB 全文索引支持中文 ngram 解析器。

**目标**

- 访客打开站点即可提问，回答**只基于公开文章的检索结果**，并给出可点击的文章引用。
- 没有检索结果时明确说明未找到，**不使用模型通用知识作答**。
- 模型走 OpenAI 兼容接口，可通过配置切换供应商。
- 游客会话留在前端内存；登录用户的会话落库、可续聊。
- 成本可控：日配额、来源限额、并发上限、上下文预算、输出上限；开关关闭时后端拒绝请求。

**参考 kumo 的部分**：编排与模型调用分离、流式事件归一（正文增量 / 工具状态 / 结束）、动态资料以系统信息注入、流式取消与背压、限流 fail-open。
**不参考的部分**：每用户 Agent 实例、控制面 reconciler、MCP 工具网关、多 Provider 凭据管理与审批。

## 二、已确认的取舍

| 项 | 结论 |
|---|---|
| 知识来源 | 只基于站内公开文章；无命中就说不知道，不使用通用知识兜底 |
| 检索 | P0 使用数据库全文索引（中文 ngram）+ 文章分块；向量检索留到 P2 评估 |
| 分块所有权 | 归内容域，检索接口放 `content.proto`，重建由内容域后台任务负责 |
| 角色 | P0 只保留单一「博客助手」，现有五个角色不再暴露 |
| 节奏 | 按 P0 → P1 → P2 分期，先完成 P0 |

## 三、分期与交付

### P0 · 可用版本

| 交付 | 内容 |
|---|---|
| 数据 | 会话表、消息表、内容域分块表；公开文章的增量分块与删除任务 |
| 协议 | `ai.proto`（会话 CRUD）；`content.proto` 增加分块检索；`ai.api`（流式问答 + 会话 + 额度） |
| 后端 | 开关校验、身份解析（登录/游客）、配额、检索、上下文组装、模型流式调用、SSE 事件映射 |
| 前端 | 流式客户端（缓冲解析、可取消）、单一助手 UI、引用卡片、额度与错误提示；打开开关挂载 |
| 部署 | 模型端点/密钥/模型名/预算/配额配置；确认 Traefik 入口的超时与流式行为 |

**验收**

- 游客提问得到基于公开文章的回答，引用可点击；换一条无关问题，回答明确说明站内没有找到，且不含通用知识推理。
- 草稿、私密、评论可见、已删除文章无法被检索到（用测试文章验证）。
- **文章从公开改为私密或删除后，其分块被清除，再次提问检索不到。**
- **站点开关关闭时，直接请求 AI 接口被后端拒绝，不产生检索与模型调用。**
- 额度耗尽、上游超时、客户端断开三种情况都有明确表现，且断开后上游请求被取消。
- 未开启开关时，前端不挂载助手。

### P1 · 会话与体验

- 登录用户的会话列表、历史消息、续聊、删除。
- 回答中的引用以卡片展示（标题 + 链接 + 片段摘要）。
- 前端支持停止生成、失败重试、错误分类提示。
- 助手消息记录 token 用量。

**验收**：换设备登录后可继续此前的会话；停止生成后上游请求结束。

### P2 · 能力扩展

- 模型自主调用只读工具（读取指定文章、列出近期文章），限制最大轮次并展示工具状态。
- 评估混合检索（关键词 + 向量），按评估结果决定是否引入。
- 管理端查看用量与失败分布（按日聚合）。

## 四、数据表与所有权

完整 DDL 落在 `protocol/sql/`，此处只记职责与必须存在的约束。

| 表 | 归属 | 职责 | 必须存在的约束 |
|---|---|---|---|
| `t_ai_session` | AI 域 | 登录用户的一次对话：标题、模型、最近活跃时间 | 按用户 + 时间检索；删除会话时级联清理消息；标题取首个问题的截断文本 |
| `t_ai_message` | AI 域 | 会话内消息：角色、正文、token 用量；工具调用快照列为 P2 预留 | 按会话 + 序号检索；游客消息不落此表 |
| `t_article_chunk` | 内容域 | 公开文章的分块，检索的基本单位：所属文章、序号、标题路径、正文、截断摘要 | 全文索引支持中文分词；按文章 id 可批量重建与删除；只存公开且未删除的文章 |

**分块归内容域**：AI 域不直接读文章表或分块表，只调用内容域的检索接口；分块重建与删除由内容域的缓存/索引任务负责。片段摘要为**正文截断**，不调用模型，不产生额外成本。

**重建载体**：内容域后台任务按 `t_article.updated_at` 水位轮询，增量重建；文章转为非公开或软删除时，同一流程删除其分块；**硬删除**由 `BatchDeleteArticles` 在同一事务内删块，重建任务同时清理 `article_id` 已不存在的孤儿块。重建是「先删旧块再插新块」的事务操作，失败保留旧块并记录日志。

## 五、接口清单

**读者端（`protocol/api/app/ai.api`）**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/ai/chat/stream` | 问答流（SSE）；登录可选，游客需合法设备标识 |
| GET | `/api/v1/ai/quota` | 今日剩余额度，供前端展示 |
| GET | `/api/v1/ai/sessions` | 会话列表（仅登录） |
| GET | `/api/v1/ai/sessions/:session_id/messages` | 会话消息（仅登录，校验归属） |
| DELETE | `/api/v1/ai/sessions/:session_id` | 删除会话（仅登录，校验归属） |

流式端点单独成组并启用 SSE；其余端点走常规 JSON 信封。**`chat/stream` 与 `quota` 在网关侧校验站点开关**，关闭时返回明确业务错误；会话列表/历史/删除不调用模型，只校验登录与归属，不随开关关闭。

**RPC（`protocol/proto/blog/`）**

- `ai.proto`：`CreateSession`、`ListSessions`、`GetSession`、`ListMessages`、`AppendMessage`、`DeleteSession`
- `content.proto` 扩展：`SearchArticles`——入参为关键词与条数，返回分块正文、文章标识与标题；仅在公开且未删除范围内检索；**不返回访问链接**，链接由网关按站点地址与文章路由拼装

## 六、流式事件与前端交互

| 事件 | 关键字段 | 前端处理 |
|---|---|---|
| `meta` | 会话标识、是否游客、剩余额度 | 建立会话态，展示额度 |
| `tool` | 工具名、阶段、摘要、引用列表 | P0 只用于检索：开始时显示「检索站内文章」，完成时渲染引用卡片 |
| 无命中 | `tool` 完成（零引用）→ `delta` 固定文案 → `done` | 按正文展示「站内没有找到相关内容」，不触发错误重试；该路径不调模型 |
| `delta` | 文本增量 | 追加到当前助手气泡 |
| `done` | token 用量 | 结束气泡，解除输入禁用 |
| `error` | 错误码、文案 | 区分额度、超时、上游失败并给出重试 |
| 心跳 | 注释帧（`: ping`） | 不产生业务事件，解析时跳过 |

前端要点：

- 用 `fetch` + `ReadableStream`，按空行切帧并**保留跨 chunk 缓冲**；不使用 `EventSource`（不支持 POST 与自定义头）。
- 用 `AbortController` 实现「停止生成」，断开后不保留半截消息。
- 登录用户提交 `session_id`；游客只带最近若干轮，服务端会再次裁剪。
- 正文按 Markdown 渲染并做 HTML 白名单清洗，链接带 `rel="noopener"`。

## 七、检索与索引作业

1. 内容域任务按 `updated_at` 水位发现文章变更，重建或删除对应分块。
2. 检索时取问题关键词，在分块上做全文匹配，得分排序取 topK。
3. 同一文章只保留得分最高的若干块，返回文章标识、标题与片段正文。
4. 无命中、索引为空或检索失败时，编排告知「站内没有找到」，不生成通用知识回答，也不回落到标题/标签等宽泛匹配。

**已知限制**：中文 ngram 默认分词长度为 2，单字查询命中率低；索引大量变更后需要重建索引（`OPTIMIZE TABLE` 或等待 InnoDB 自动合并）才能合并碎片。

**待验证**：Traefik 入口下流式响应的实际行为（是否立即下发、空闲超时是否会断开长流），联调时用真实网络确认。

## 九、配置与部署

- **模型**：端点、密钥、模型名、温度、输出上限、超时。超时是**整条流的总时限**（含生成），默认 2m，慢供应商需要调大；密钥只来自环境变量或 Secret。客户端**惰性构造**：开关关闭时不需要模型配置即可启动；开关开启但配置缺失时，请求期返回明确错误。
- **预算**：历史轮次、检索条数、单块与总字符上限、prompt 上限；游客请求中携带的历史先截到 50 条、单条 2000 字，请求体上限 64KB，服务端再按预算裁剪。
- **配额**：游客日额度、登录用户日额度、**来源（IP）补充限额**、全站并发上限。并发与日计数都用 Redis，多副本共享；流结束或断开时递减。并发计数带租约/TTL，进程崩溃后由过期自愈，不会把后续请求一直挡在并发上限外。
- **网关与入口**：流式路由沿用通知流的 SSE 写帧方式（`X-Accel-Buffering: no` 在 Traefik 下不生效）；SSE 的响应写出不受 `readTimeout` 影响（`writeTimeout` 默认不限），心跳 15s 远小于 `idleTimeout`，无需额外的入口超时配置。
- **开关**：`is_ai_assistant` 默认关闭，按环境开启；网关读取站点配置（走缓存）校验，关闭时拒绝 `chat/stream` 与 `quota`；会话 CRUD 不受影响。
- **日志**：不记录问句、回答、检索片段与文章正文；只记录请求标识、模型、用量、耗时与错误码，上游错误只记状态码与错误类型。

## 十、测试与验收

- **单元**：分块与标题路径（含标题层级）、预算裁剪顺序、流式事件映射、前端 SSE 跨 chunk 解析（含心跳注释帧）、配额判定。
- **集成**：用假的上游流式服务验证增量、工具事件、结束与错误；验证客户端断开后上游取消；验证模型配置缺失时的错误路径。
- **权限**：构造公开、私密、草稿、评论可见、已删除文章，断言只有公开文章可检索；文章转为私密后断言分块被删除；**硬删除文章后断言分块被删除、孤儿块被清理**；只出现在文章标题或章节标题的关键词也能命中。
- **历史方向**：20 条消息时断言取到最近 12 条（首条为第 9 条），而不是最早的 12 条。
- **日志白名单**：构造检索失败与上游失败，断言日志只有错误类型/状态码，不含问句与正文。
- **开关**：关闭站点开关后直接请求 `chat/stream` 与 `quota`，断言被拒绝且没有模型调用；会话 CRUD 仍可访问。
- **会话归属**：传入他人或不存在的 `session_id` 时，在 `meta` 之前返回错误，不新建会话。
- **游客历史**：60 条输入截到最近 50 条，单条截到 2000 字，非法角色丢弃。
- **无命中**：构造无命中问题，断言不调用模型、返回固定文案。
- **并发**：模拟流未正常结束（租约过期），断言并发计数自愈。
- **端到端**：游客提问 → 引用 → 无命中提示 → 额度耗尽；登录用户建会话 → 换设备续聊。

## 十一、风险与未决

| 风险 | 应对 |
|---|---|
| 长尾提问检索命中率低 | 接受「说不知道」；P2 评估向量与重排，不以通用知识兜底 |
| Traefik 长流被空闲超时断开 | 心跳 15s 远小于 `idleTimeout`；若仍被断，先查链路中间的空闲超时 |
| 匿名刷取导致成本失控 | 身份日配额 + 来源限额 + 并发上限 + 开关止损 |
| 分块质量影响回答 | 分块以标题为界、控制块长；P2 评估向量与重排 |
| 模型输出冒用站内口吻 | 人设中约束引用格式与「不知道就说不知道」，引用必须带文章链接 |
| 日志泄露问句或正文 | 日志字段白名单化，只记录用量与错误码，代码评审时检查 |
| 并发计数未递减（进程崩溃） | 租约/TTL 自愈；监控并发计数与上限的差距 |

**未决**

- P1 会话列表是否需要跨模型/跨端筛选。
- P2 是否引入向量检索，取决于 P0 上线后的检索命中率与用户反馈。
- 游客历史在客户端的保留时长与上限，P0 先取「最近 6 轮 / 4000 字符」，上线后按实际体验调整。

## 十二、评审修订（2026-11-04）

按代码与部署现状核对后，对初版计划做了以下修正：

1. 明确「只基于检索结果作答」，删除「通用知识兜底」的表述，并写入验收与不变量。
2. 游客会话统一为「前端携带、服务端裁剪」，删除「服务端内存保留」，避免与多副本冲突。
3. 分块表改归内容域（`t_article_chunk`），检索放 `content.proto`，补重建载体与「转非公开即删块」。
4. 入口代理由 nginx 改为 Traefik，部署项按 Traefik 的超时与缓冲行为重写。
5. 补后端开关校验、模型客户端惰性构造、来源限额与 Redis 并发计数、日志脱敏、心跳、会话标题、P0 引用载体与链接拼装位置。
6. 数据库 ngram 从「待验证」改为确定项，并补充分词长度与索引合并的限制。

### 第二轮（2026-11-04）

按复核结论再修：

7. 硬删除文章时同事务删块，重建任务清理孤儿块。
8. 删除全文索引的标题/标签回退，统一为「无命中即止」。
9. 并发计数带租约/TTL，进程崩溃后自愈。
10. 定义无命中事件序列：`tool` 完成（零引用）→ `delta` 固定文案 → `done`，不调模型。
11. 开关门禁收窄为 `chat/stream` 与 `quota`，会话 CRUD 不受影响。
