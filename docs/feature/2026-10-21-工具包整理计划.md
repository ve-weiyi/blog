# blog-cloud 工具包整理计划

> 日期：2026-10-21
> 范围：`blog-cloud/infra/**`、`cmd/api/{app,admin}/internal/common/**`
> 定位：**结构调整计划，日期快照**。落地后代码为唯一真相，本文不逐字追更。
> 约束：只整理目录、职责与重复实现，不改业务行为；不重写生成代码。

---

## 一、背景与目标

`infra/` 目前有 **34 个包**、约 **6.0k 行生产代码 + 4.7k 行测试**。目录是按开发过程逐步长出来的：只有 `biz/`、`constants/` 两个容器，其余 18 个包全部平铺，同类能力分散在不同层级，读者无法从目录判断一个包的归属边界。

本次整理要达到三个目标：

1. **目录可读**：看到路径就能判断「这是哪个边界、解决哪类问题」；
2. **职责单一**：一个包只有一个变化理由，混合职责拆开；
3. **消除重复**：同一份工具代码只保留一处，`cmd/` 中不再有 `common`、`apiutils` 这类收纳层。

## 三、问题清单

| # | 问题 | 证据 / 说明 |
|---|---|---|
| 1 | **没有统一分层维度** | 同属认证的 `tokenx`、`oauthstate` 平铺，而 `bizcookie`、`bizheader` 在 `biz/` 下；`limitx` 藏在 `middlewarex` 下却被 svc 直接使用 |
| 2 | **`biz/` 是无意义前缀** | 5 个包之间没有共同职责，`biz` 只是「业务」这个万能词；包名还重复（`biz` + `bizcode`） |
| 3 | **`constants/` 是混合桶** | `config.go` 是站点配置键；`enums` 是 DB 业务枚举；`cachekey` 是 Redis 键；`mailtemplate` 是模板渲染 + embed 文件，不是常量 |
| 4 | **包职责混装** | `requestx` = IP 解析 + 密码策略 + 上传参数；`metax` = incoming metadata + outgoing metadata；`bizheader` = HTTP 头 + gRPC 头 + Bearer 解析；`dbnotify` 名字通用，实际写死 RBAC 三张表 |
| 5 | **`cmd` 内重复工具** | `apiutils/batch.go` 两边逐字节相同；`account.go` 仅 `svc`/`types` 导入不同；STOMP 认证器两份近似；操作日志脱敏两份；`ConnectRedis` 三份、Nacos 引导三份（后两者属装配，另计） |
| 6 | **死代码 / 未接线** | `cachekey.InboxReadPrefix`、`GetInboxReadKey` 零引用；`interceptorx.ServerAuthInterceptor` 零引用且与 `ServerMetaInterceptor` 函数体相同；`ClientLogInterceptor` 未接线；`metax.GetApiTokenFromCtx` 零引用 |
| 7 | **命名不统一** | 一半包带 `x`、一半不带；`staticfile`/`dbnotify`/`constants` 与 `responsex`/`storex` 并存 |
| 8 | **`common/` 目录** | 违反 `go.md`「包名禁止 util/helper/common/misc」；`apiutils` 本身也是 util 语义 |

### 3.1 已知但本轮不处理的耦合

`responsex`（HTTP 响应出口）→ `bizerr` → `google.golang.org/grpc/status`：HTTP 层因此间接依赖 gRPC。当前这是「错误码跨边界编解码」的刻意设计，不属于目录整理范围；若将来要解耦，应拆成纯错误类型与 gRPC 编码两层，另立设计任务。

## 四、目标结构

按「这个包在哪个边界上」分组，深度最多 3 层，保留现有包名以减少语义 churn。

```
infra/
├── http/                     # HTTP 边界
│   ├── responsex/            # 统一响应 + 错误→HTTP 映射
│   ├── requestx/             # ClientIP、上传参数规范化（密码策略拆出）
│   ├── middlewarex/          # 反重放 / 设备 Cookie / 令牌 / 限流
│   │   └── limitx/           # 限流器（中间件与 svc 共用）
│   ├── routex/               # 路径规范化与匹配
│   ├── headerx/              # 原 bizheader：头名 + Bearer 解析
│   ├── cookiex/              # 原 bizcookie：设备 Cookie
│   ├── staticfile/           # go-zero 静态文件路由
│   └── swaggerx/             # Swagger 操作枚举
├── grpc/                     # gRPC 边界
│   ├── interceptorx/         # 客户端/服务端拦截器
│   └── metax/                # 可信 metadata（incoming / outgoing 分文件）
├── auth/                     # 认证与身份
│   ├── tokenx/               # 令牌服务（codec/、store/）
│   ├── oauthstate/           # OAuth state
│   ├── identityx/            # 用户/游客 ID 形态
│   └── passwordx/            # 密码策略（从 requestx 拆出）
├── store/                    # Redis / MySQL 访问
│   ├── storex/               # KV / Member 原语 + Redis 实现
│   ├── captchax/
│   ├── otpx/
│   ├── presencex/            # 在线状态存储（实现 stompws PresenceManager）
│   ├── queryx/               # GORM 查询构建
│   └── gormlogx/             # GORM 日志适配
├── messaging/                # 跨进程事件与实时推送
│   ├── notifyx/              # 通知事件契约
│   ├── dbnotify/             # 写库后失效事件（GORM 回调）
│   └── stompwsx/             # 在线推送钩子 + STOMP 认证器
├── errors/                   # 错误契约
│   ├── bizcode/
│   └── bizerr/
├── domain/                   # 领域常量与内容模板
│   ├── configkey/            # 原 constants（站点配置键）
│   ├── enums/
│   ├── cachekey/
│   └── mailtemplate/
├── collectx/                 # 列表批量查询辅助
└── redactx/                  # 日志脱敏
```

`cmd/api/{app,admin}/internal/common/` 全部消失：

```
cmd/api/app/internal/
├── enrich/                   # 原 apiutils/account.go（网关本地类型适配）
└── stomphook/                # 聊天室钩子（仅 app）

cmd/api/admin/internal/
├── enrich/
├── sse/                      # 原 common/sse
└── stomphook/                # 通知事件钩子（仅 admin）
```

共用部分上移：

- `apiutils/batch.go` → `infra/collectx`（或 vkit，见 §六 决策 2）；
- STOMP 认证器 → `infra/messaging/stompwsx/auth.go`（支持 `AllowGuest`）；
- 日志脱敏 → 抽成共享包，`interceptorx` 与 admin 操作日志共用。

## 五、分阶段执行

| 阶段 | 内容 | 提交边界 | 验证 |
|---|---|---|---|
| **0. 基线** | 记录 build/test/race 结果 | — | `GOWORK=off go build ./...`、`go test ./...`、`go test -race ./infra/...` |
| **1. 删死代码** | 删除 §三 问题 6 的 4 处零引用；`ratelimit_middleware.go` 是 goctl 模板，保留 | 1 个 commit | build + test |
| **2. infra 重组** | 按 §4.1 `git mv` + 更新 import；按 `http/`、`grpc/`、`auth/`、`store/`、`messaging/`、`errors+domain` 分组提交 | 6 个 commit | 每步 build；`grep -r 'infra/biz\|infra/constants'` 为空 |
| **3. 拆分职责** | `requestx/password.go` → `auth/passwordx`；`metax` 拆 incoming/outgoing；`headerx` 中 2 个 RPC 头移到 `grpc/metax` | 1–2 个 commit | build + 单测 |
| **4. cmd 去重** | `batch.go` → `collectx`；`account.go` → `enrich`；STOMP auth 合一；`sse` 去 `common`；脱敏合一 | 2–3 个 commit | build + test |

### 5.2 阶段 2：移动规则

- 一律使用 `git mv` 保留历史；
- 移动与包名变更放在同一提交，避免出现「目录名与包名不一致」的中间态；
- import 路径批量替换后跑 `gofmt -w` / `goimports -w`；
- 每次提交后跑 `GOWORK=off go build ./...`，失败只修 import，不改逻辑；
- 本轮改名都不是「仅大小写」变更，不触发 macOS 大小写不敏感的三步改名流程；若出现仅大小写改名，按 `workflow.md` 三步执行。

### 5.3 阶段 4：cmd 去重说明

- `apiutils/account.go` 两边只差 `svc`/`types` 导入，但依赖各自网关的生成类型，**不做跨网关共享**；各自迁移为 `internal/enrich`，保留薄适配层；
- `apiutils/batch.go` 中的 `BatchQuery`/`BatchQueryMulti` 仍被 app logic 使用，上移为 `infra/collectx`；`ExtractFields`/`ExtractMultiFields` 一并保留；
- 两个 STOMP 认证器合并为一个类型，用 `AllowGuest` 区分：app 允许游客（`login`/`passcode` 均为空时放行），admin 要求必须登录；
- `admin/internal/common/sse` 只有一个消费者，不上移 `infra`，只去掉 `common` 层。

## 九、风险与回滚

| 风险 | 应对 |
|---|---|
| import 路径大范围变更导致漏改 | 分阶段、分组提交；每步 build；最后 grep 旧前缀兜底 |
