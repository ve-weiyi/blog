# 死信队列检查与重放

> 适用于 `vkit/cmd/mqdlq`。工具只操作 RabbitMQ，不读写数据库。

## 一、前置

- 设置 `MQX_RABBIT_URL`（含 vhost）；工具不会回落默认地址。
- 确认目标队列名。通知域按事件拆队列，死信队列由消费者自动声明为 `<消费组>.dlq`：
  - `blog.rpc.notification.email.dlq`
  - `blog.rpc.notification.sms.dlq`
  - `blog.rpc.notification.inbox.dlq`

## 二、查看

默认只列出，不会确认或删除消息；每条消息检查后会 `Nack(requeue=true)` 放回队列。

```bash
go -C vkit run ./cmd/mqdlq \
  -queue blog.rpc.notification.email.dlq \
  -limit 50
```

输出包含 `event_id`、原 routing key、attempts、failed_at、body 长度与截断后的错误；**不打印消息体**。

## 三、重放

先修根因，再重放。重放只把消息投回原 exchange/routing key，不会修改业务数据。

```bash
# 重放单条
go -C vkit run ./cmd/mqdlq \
  -queue blog.rpc.notification.email.dlq \
  -event-id 0192f... \
  -replay -yes

# 重放检查到的全部（受 -limit 约束）
go -C vkit run ./cmd/mqdlq \
  -queue blog.rpc.notification.email.dlq \
  -all -replay -yes -limit 100
```

| 参数 | 含义 |
|---|---|
| `-queue` | 必填，死信队列名 |
| `-limit` | 本次最多检查多少条，默认 100 |
| `-event-id` | 只重放指定事件 |
| `-all` | 重放检查到的全部消息 |
| `-replay` | 真正重放；缺省只列出 |
| `-yes` | 确认重放，`-replay` 必填 |
| `-force` | 允许 `replay_count >= 3` 的消息再次重放 |
| `-destination` | 原目的地头缺失时的兜底 exchange |
| `-routing-key` | 原 routing key 头缺失时的兜底值 |

## 四、安全规则

- **默认只读**；`-replay` 必须同时带 `-yes`。
- 发布成功后才 `Ack`；发布失败会 `Nack(requeue=true)` 并停止。
- 保留原 `mqx.event_id`，消费方仍按事件 ID / 业务键去重；重放不会产生第二条业务记录。
- 每次重放写入 `mqx.replayed_at`、`mqx.replay_count`，超过 3 次需要 `-force`。
- 不打印消息体，避免验证码、手机号、邮箱进入终端或日志。
- 同一时间只让一个操作者重放同一个队列，避免重复消费与重复确认。

## 五、outbox dead 行

outbox 的 dead 事件不在 RabbitMQ，而在 `t_outbox_event` 表。先查：

```sql
SELECT id, event_id, destination, routing_key, retry_count, last_error, occurred_at
FROM t_outbox_event
WHERE status = 'dead'
ORDER BY id DESC
LIMIT 50;
```

修完根因后，把指定行放回待投递队列，relay 会自动接管：

```sql
UPDATE t_outbox_event
SET status = 'pending', retry_count = 0, next_attempt_at = NOW(3), locked_at = NULL, lock_token = ''
WHERE id = ? AND status = 'dead';
```

不要批量重置所有 dead 行；先确认 `last_error` 是已修复的问题。

## 六、重放仍失败怎么办

1. 先看 `mqx.error` 与消费日志，确认根因是否修复；
2. 根因未修复时重放只会再次进入死信，不要反复 `-force`；
3. 需要批量检查时用 `-limit` 分批，先列出、再决定重放范围；
4. 死信持续增长时优先处理积压告警，而不是直接清空队列。
