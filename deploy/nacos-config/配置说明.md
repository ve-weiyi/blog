# Nacos 配置说明

> **本文件是** Nacos 配置的**源头与发布方式** —— 三种部署形态共用同一份配置。

应用的运行配置**不在 K8s 清单里**，而是由 Nacos 下发。本目录是这些配置的源头。

三个服务各一份，两个环境：

```
nacos-config/
├── publish.sh     发布脚本
├── prod/          服务运行在集群内，三个服务各一份
└── test/          服务运行在集群外（本机），三个服务各一份
```

**约定：文件名即 Nacos 的 dataId**，目录名即命名空间。所有配置的 group 一律为 `veweiyi.cn`。

## 两个环境的区别

| | `test` | `prod` |
|---|---|---|
| blog 服务在哪 | **集群外**（本机） | **集群内** |
| 中间件地址 | 节点公网 IP + hostPort（`159.75.154.50`） | 集群内服务短名（`mysql` / `redis` / `rabbitmq`） |
| `AppRpcConf` | `127.0.0.1:9120`（blog-rpc 同样跑在本机） | `blog-rpc:9120` |

`test` 用来在本机跑服务、连集群的中间件，改配置不会影响线上；
`prod` 是集群内运行的那一份，**k8s 部署只保证这一份的正确性**。

> 本地跑 `test` 时，Nacos 在集群里且这两个端口都未对外暴露，**两个都要转发**：
> ```bash
> kubectl -n blog port-forward svc/nacos 8848:8848 9848:9848
> ```
> - **8848**：HTTP，客户端用它**登录换 token**
> - **9848**：gRPC（= 8848 + 1000），客户端用它**拉配置**
>
> **只转发 8848 会失败**，且症状有误导性：SDK 日志里报
> `dial tcp 127.0.0.1:9848: connect: connection refused`，
> 而应用侧抛的却是"read config from both server and cache fail"，
> 看起来像 Nacos 里没有这条配置。集群内不存在这个问题——`nacos` Service 已同时暴露 8848 与 9848。
>
> 然后以 `-nacos-host=127.0.0.1 -nacos-namespace=test -nacos-group=veweiyi.cn` 启动本地服务。

## 发布

在仓库根目录：

```bash
# 发布 test 与 prod 全部 6 条
bash deploy/nacos-config/publish.sh

# 只发 prod
bash deploy/nacos-config/publish.sh prod

# 只发 prod 的 app-api
bash deploy/nacos-config/publish.sh prod app-api
```

脚本走集群内的 Nacos（`nacos:8848`），需要 `kubectl` 可用。
kubeconfig 不在默认位置时用 `KUBECONFIG_FILE=/path/to/kubeconfig bash ...` 指定。

## 关于认证

**发布走的是 Nacos 的 server-identity 头，不是用户登录**：

```
POST http://nacos:8848/nacos/v3/admin/cs/config
Header: serverIdentity: security          ← NACOS_AUTH_IDENTITY_KEY / _VALUE
```

这与 `deploy/k8s/env.yaml` 里的 `NACOS_AUTH_IDENTITY_KEY` / `NACOS_AUTH_IDENTITY_VALUE` 对应。

**为什么不用账号密码**：Nacos 3.x 的控制台登录与核心 API 是两条独立通道，
且 3.1.1 的建表脚本**只建表不插数据**——首次启动后 `users` 表是空的，没有任何管理员账号，
控制台登不进去。管理类操作因此在集群内用 server-identity 完成（该头由服务端校验，不经用户体系）。

> **控制台目前登录不了**（`https://nacos.veweiyi.cn/`），原因待查：
> 库里 `nacos` 用户的存在与密码哈希都已验证正确（是 `nacos` 的合法 bcrypt），
> 但控制台 `/v3/auth/user/login` 仍返回 `User not found`。
> 需要人工进控制台时，先用 `POST /v3/auth/user/admin` 重新生成一个密码试试。
> 应用侧不受影响——它用 `NACOS_USERNAME` / `NACOS_PASSWORD` 走**客户端认证**，
> 与本文档讲的发布通道（server-identity）是两条路。

## 与清单的对应关系

改动本目录后，**必须保证与以下三处一致**，否则服务拉不到配置：

| 项 | 在哪 |
|---|---|
| group | `deploy/k8s/app/nacos-config.yaml` 与 `deploy/docker/.env` 的 `NACOS_GROUP` |
| 命名空间 | `deploy/k8s/app/nacos-config.yaml` 的 `NACOS_NAMESPACE`（k8s 用 `prod`） |
| dataId | 各 Deployment 的 `-nacos-data-id=<服务名>` |

配置里的凭据（MySQL / Redis / RabbitMQ / MinIO）目前与 `deploy/k8s/env.yaml` 的 `blog-env` 手工保持一致——
**改一处要记得改另一处**，两边没有自动同步。
