# Go 代码设计规范

**通用设计规则（包与职责、接口与耦合、并发安全、错误与边界、一致性与简洁）以 `golang-design` skill 为唯一真相源；本文件只记本仓特有约定。**

## 设计取向

遵循 Go 极简哲学：高内聚、低耦合、可商用、可测试，拒绝过度设计。

- 简单配置用值类型，复杂配置用 Option 模式。
- 避免全局变量/全局客户端，依赖显式注入。
- 构造函数用 `NewXXX()`，不用 `New()`。
- 工具模块保持通用；错误返回上层，由上层决定是否记录日志，错误信息用英文。
- 目录、文件、类型、属性命名与排序遵循行业惯例，避免魔法值。
- 设计审查从**职责过载、过度抽象、重复设计、不合理设计、并发隐患**五个角度进行；不考虑兼容旧数据，以最优设计为目标，可借鉴成熟项目。

## 注释

- 只写**提供什么功能**，不写不提供什么；**只说自己，不指路**，不写“见某文件/某文档/上游实现”。
- **留理由，不留历史**：写不变量、契约与踩过的坑，不写演进过程；跨文件、跨实现的对照归文档。
- 同包内指名函数/字段是事实，不算指路；批量精简注释按整行处理，避免误删代码。

## 包命名

- 包名一句话说清目的，禁止 `util` / `helper` / `common` / `misc`。
- 选名前先查是否与依赖包重名（go-zero 已占用一批 `*x` 名）：
  ```bash
  find ~/go/pkg/mod -maxdepth 6 -type d -name <候选名>
  ```
- 吞错的函数必须标 `// Deprecated` 并指向带 error 的版本。

## 测试

**目标：用尽量少的用例守住主流程与不变量，不为实现细节堆测试。**

- 只测主流程、关键错误路径与不变量；构造器 nil 参数、getter、nil map 等低价值分支不单独成测，需要时合并进该单元的主测试。
- 一个 `Test` 对应一个行为；同类边界与错误分支用表驱动 + `t.Run` 收敛，用例名说明场景与期望。
- **必须有断言**（`t.Error` / `t.Fatal` 或断言库）；`t.Log` / `fmt.Println` 只能辅助定位。
- 测试文件与被测包同目录；默认 `xxx_test` 黑盒包，只有验证未导出符号时才用同包；辅助代码用 `t.Helper()`，无 Test 函数的 helper 文件可以存在。
- 测试默认离线：优先内存替身、本地测试服务器，不依赖本机已启动的数据库、缓存或消息队列。
- 需要真实凭证或会产生外部副作用的验证，优先做成可人工执行的诊断程序；确需留在测试目录时，必须由环境变量显式开启，缺失时 `t.Skip`，已设置但连接/上传失败时 `t.Fatalf`，不得硬编码凭据、bucket、DSN。
- 新增环境变量时同步维护环境变量模板，只写变量名、说明与占位值。
- 禁止硬编码开发者机器路径；夹具放仓库固定位置或临时目录，外部夹具通过环境变量传入。
- 不用 `time.Sleep` 等待异步结果；优先可快进的测试存储、可注入时钟或同步信号，无法避免时用最小等待并注释原因。
- 测试不得永久修改进程级全局状态，用 `t.Cleanup` 还原（logger、环境变量、全局 client 等）。
- 动了并发相关代码跑 `-race`；协议一致性、并发/竞态等关键不变量用例不因“减少测试数量”而删除。
- 声称“重构不改变行为”前先取基线：改前存输出快照，改后逐字节比对；旧实现还在 git 里时，优先写临时对照测试当 oracle。
