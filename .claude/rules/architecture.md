# 架构总览

本文件只写**不随代码变动的分层规则**。仓库有哪些模块、模块内部目录怎么分，**以代码为准** —— 规则里不复制这类清单，否则代码一改规则就成错的。

## 后端分层

```
┌──────────────────────────────────────────────────────┐
│  HTTP 网关层（api）                                     │
│  handler → logic → svc                                │
│  handler: 路由注册 + 参数校验 + 响应封装                  │
│  logic:   业务编排（经 RPC client 调用下游服务）           │
├──────────────────────────────────────────────────────┤
│  RPC 服务层（rpc）                                      │
│  handler → logic → svc                                │
│  handler: gRPC server 方法实现                         │
│  logic:   业务逻辑                                     │
├──────────────────────────────────────────────────────┤
│  应用基础设施（infra）                                   │
│  中间件、拦截器、限流、响应封装、认证 token、框架封装         │
├──────────────────────────────────────────────────────┤
│  公共库（vkit）                                          │
│  adapter / x 两层，判据见下                             │
└──────────────────────────────────────────────────────┘
```

层间约束：

- `handler` 不承载业务逻辑；`logic` 不依赖 HTTP / DB 类型（框架语义不侵入业务层）
- 依赖单向：上层可依赖下层，**下层不得反向依赖上层**

## 公共库（vkit）两层

判据是**面向什么**，不是"用不用标准库"：

| 层 | 面向什么 |
|---|---|
| `adapter/` | **具体外部系统** —— 有地址、凭证、连接 |
| `x/` | 与具体系统无关的**通用能力**（可依赖轻量单一用途的库） |

- 新包先问一句：面向具体外部系统吗？不是 → `x/`
- 纯本地文件/格式读写（无外部依赖、无状态）→ `x/`
- 依赖单向：`adapter/` 可以依赖 `x/`，**`x/` 不得反向依赖 `adapter/`**
- **面向具体第三方框架的封装不进 vkit** —— 它只服务于使用它的那一个应用，放该应用的 `infra/`（如 gorm 日志封装放 `blog-cloud/infra/`）。公共库不为单个应用绑定框架组合
